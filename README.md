# 牛来（niulai）

> A 股股票和交易所 ETF 的诊断与研究工作台。

## 新闻稿

很多行情工具可以告诉使用者「今天涨了什么」，却很难回答「这个结论依据什么、过去是否验证过、明天应该如何继续观察」。牛来把数据、规则、结果和账户记录放在同一条可回看的链路里：从供应商同步行情与公司行动到本地 PostgreSQL，在网页上查看复权 K 线、指标、信号和诊断，用白话条件组合策略，自动巡检全市场，并把历史回测和账户调仓建议放在同一套规则下解释。

牛来面向需要自己核对依据的小团队和个人研究者。它以日线和收盘后同步为主，数据和回测结果仅供研究，不构成投资建议，也不连接券商或自动下单。

## 常见问题

### 牛来解决什么问题？

它把「看行情」「看信号」「验证方法」「记录持仓」拆成连续的步骤：

- **先看结论：** 首页、热点和指数页面汇总最近交易日的市场状态、策略结果和自选股新信号。
- **再看依据：** 证券页面提供股票或 ETF 的日线、复权口径、指标、信号、诊断和策略买卖点。
- **验证方法：** 策略可以用白话条件定义，查看全市场巡检结果、单只证券回测和组合回测。
- **持续跟踪：** 自选股和账户保存各自的研究对象、持仓、流水及每日调仓建议；每条建议附带命中的规则和可核对的理由。
- **维护数据：** 首次配置数据源后执行历史回补，之后按计划增量同步、核对缺口并安排可补的数据。

### 数据从哪里来？

当前接入同花顺金融数据服务。原始响应保存在通用记录库，常用行情、公司行动和财务数据再投影到类型化表。股票指标使用等比前复权价格；交易所 ETF 使用供应商提供的 ETF 行情口径。数据集、覆盖范围和限制见 [数据目录](docs/interfaces/dataset_catalog.md) 与 [同花顺接口](docs/interfaces/hithink_api.md)。

### 回测代表未来收益吗？

不代表。回测是按历史数据重放规则，用于比较方法和检查规则是否符合预期；成交时点、价格口径、交易成本、涨跌停和历史证券覆盖范围都有明确边界，详见 [回测规则](docs/domains/backtest.md)。历史表现不能保证未来结果。

### 如何快速启动？

需要 Docker Engine 和 Compose 插件。下面的命令会下载当前 `main` 的部署文件，并在本机启动 PostgreSQL、niulai 和可选的一键升级助手：

```bash
mkdir niulai && cd niulai
curl -O https://raw.githubusercontent.com/duoyuli/niulai/main/deploy/compose.yml
curl -o .env https://raw.githubusercontent.com/duoyuli/niulai/main/deploy/.env.example
docker compose up -d
```

打开 <http://127.0.0.1:8080/>。首次管理员账号和密码读取 `.env` 中的 `NIULAI_ADMIN_USER`、`NIULAI_ADMIN_PASSWORD`；示例文件提供了可启动的默认值，部署到共享网络前应立即修改。管理员登录后按页面引导配置数据源 API Key，再到「数据同步」查看回补进度。

数据库数据位于部署目录的 `data/postgres`，升级前备份位于 `backups/`。不要删除这两个目录。端口、镜像版本、数据库连接和同步限速都在 `.env` 中配置；完整步骤见 [运维手册](docs/operations/runbook.md#deployment)。

### 可以不用 Docker 吗？

可以。前端使用 Node.js 与 pnpm 构建，后端使用仓库固定的 Rust toolchain 编译，运行时需要 PostgreSQL。源码部署、测试、备份和升级步骤见 [运维手册](docs/operations/runbook.md)。

### 这个项目明确不做什么？

牛来不承诺收益，不把信号当成订单，不接收券商委托，也不自动交易。供应商权限、数据覆盖和历史缺口会影响结果；页面上的诊断和建议必须结合原始数据、规则定义和回测边界一起阅读。
