# 多用户、多账户与每日调仓建议：实现方案

> 调研笔记，不属于 Project Doc 文档库。2026-10-17 写，取代初版 [2026-10-18-account-and-rebalance.md](2026-10-18-account-and-rebalance.md)，供拍板后实现。实现时把定下来的规则写进 `docs/domains/`（新增「账户与调仓建议」）和 ADR。

## 一、要解决什么

1. 有登录：系统里有多个用户，每个用户只看得到自己的账户。**不开放注册**，用户由管理员在系统里添加并设置密码。
2. 每个用户可以建多个账户（不同券商、不同风格：保守、稳健、进取），每个账户有自己的资金和持仓。
3. 每个交易日收盘、数据同步完之后，系统自动为每个账户生成一份「明天怎么操作」的建议：卖什么、减多少、继续拿什么、买什么、买多少。
4. 两个硬要求：**用起来几乎不用动脑**；**每条建议都讲清楚为什么**，理由要有数字、能核对。

不对接券商、不自动下单。建议只是参考，用户自己去券商 App 下单。

## 二、初版方案的问题

| 问题 | 后果 | 本方案的做法 |
| --- | --- | --- |
| 没有用户登录，只有现在的一个管理员 | 需求第 1 条没有落地，账户谁都能看 | 新增用户表和角色，账户归属到用户，接口层强制隔离 |
| 每次生成都要用户选策略、填「目标持仓只数」 | 认知成本高：用户要先懂 14 个策略的区别，才能用 | 建账户时选一个风格，风格自带策略组合和仓位规则；之后每天自动出建议，什么都不用选 |
| 只在用户点按钮时生成 | 不满足「每日生成」 | 每次同步加巡检完成后，自动为所有账户生成 |
| 持仓的「卖 / 留」直接用巡检的「持有中」列表 | 巡检的持有是策略自己模拟的买入，和用户真实的买入日、成本无关；用户手动录的持仓大多会落进「无策略覆盖」，系统对它不发表意见 | 用户的每只持仓都用账户的卖出规则、按**用户自己的成本和买入日**逐只判断，不存在「没有判断」的持仓 |
| 理由只有一句命中条件，例如「5 日均线上穿 20 日均线」 | 用户不知道这个信号靠不靠谱、为什么排第一、风险有多大 | 每条建议给出：触发的规则、这个策略过去的表现、和「随便买」对比、诊断、风险金额、什么时候失效、为什么没选别的 |
| 执行后要用户回来重新录一遍持仓 | 第二天的建议基于过时的持仓，用户很快就不录了 | 每条建议旁边一个「已执行」，点一下（可改实际成交价和股数）就自动更新持仓和现金；分红送转系统自动记账 |
| 持仓股数要求必须是 100 的整数倍 | 送转股之后的零股录不进去 | 股数只要求是正整数；买入建议按交易规则取整，零股只能一次卖完 |
| 风格（保守、激进）在设计里没有体现 | 两个风格不同的账户得到的建议一样 | 风格决定策略组合、仓位上限、止损、弱市处理、追高上限 |

## 三、设计原则

**低认知成本：**
1. **每天只做一件事。** 打开「今日」，每个账户一行：「主力账户：卖 1 只、买 2 只」或「今天不用操作」。点进去是一份清单，照着做完逐条点「已执行」。
2. **不让用户做选择题。** 建账户只问名字、风格、现金和持仓；风格用三张卡片说明，不出现策略名和参数。参数都有默认值，高级设置折叠起来，绝大多数人不用打开。
3. **录入越少越好。** 持仓可以从券商 App 复制粘贴；成本和买入日可以不填；执行建议、分红送转自动记账，不用重录。
4. **用动作说话，不用术语。** 动作只有五种：卖出、减仓、继续拿、买入、不动。指标名出现时附一句白话，例如「20 日均线（最近 20 个交易日的平均收盘价）」。
5. **告诉用户「什么时候要再看」。** 每条建议带失效条件，例如「跌破 14.20 元就会建议卖出」，用户不用每天盯着。

**有理有据：**
1. **规则先于结论。** 每条建议都由明确的规则产生，页面写出是哪条规则、规则的阈值和今天的实际数值，例如「亏损 8.6%，超过本账户的止损线 8%」。
2. **证据有数字、能核对。** 策略过去 3 年在全市场的表现、和同期随便买的对比、个股诊断四个维度，都附数字；点股票名进入 K 线页，图上叠加这个策略的买卖点，自己就能看到。
3. **讲风险，不只讲机会。** 买入建议写出止损价和「最多亏多少钱、占账户百分之几」；有反面信号时写在「需要注意」里，不隐藏。
4. **讲为什么没选别的。** 列出今天有买点、但没进建议的候选和原因（仓位满了、钱不够一手、追高、弱市暂停、策略过去表现不如随便买）。
5. **可复现。** 每份建议保存当时的全部输入（持仓、现金、风格参数、行情日期、策略版本），之后再看也是当时的样子；规则改了不会改写历史建议。
6. **事后可检验。** 保存每条建议之后 5、10、20 个交易日的实际涨跌，页面给出「过去的建议准不准」。

## 四、用户与登录

### 4.1 角色

| 角色 | 能做什么 |
| --- | --- |
| 管理员 | 所有用户能做的；另外：添加用户、重置密码、停用用户；数据同步、API Key、一键升级、策略和信号的增改删 |
| 普通用户 | 自己的账户、持仓、建议；自己的自选股；查看策略、信号、指标、个股、指数、指南（只读） |

- **不开放注册。** 没有注册页和注册接口。管理员在「用户」页添加用户：填用户名、初始密码（或系统生成一个随机密码只显示一次），选角色。
- 用户登录后可以改自己的密码；管理员可以重置任何人的密码。改密码或重置后，这个用户已登录的会话全部失效。
- 停用用户：不能登录，数据保留；只有一个管理员时不能停用自己、不能改自己为普通用户，避免把自己锁在外面。
- 账户、持仓、建议只对所属用户可见，管理员也看不到别人的账户（隐私）。策略、信号是全系统共用的库。

### 4.2 第一个管理员与找回

- 第一次启动、`app.user` 为空时，用现在的 `NIULAI_ADMIN_USER`、`NIULAI_ADMIN_PASSWORD` 创建第一个管理员（没有配置时仍是 `niulai` / `niulai`，页面顶部照常提示修改）。之后这两个变量不再使用，密码只在页面上改。已部署的系统升级后用原来的账号密码登录，体验不变。
- 忘记密码：在服务器上执行 `niulai user reset-password <用户名>`，打印一个新的随机密码。
- 这条改动要写 ADR：认证从「环境变量里的单个管理员」改成「数据库中的用户」。

### 4.3 实现要点

- 密码用 Argon2id 哈希保存（`argon2` crate），不保存明文。
- 会话沿用现在的签名 Cookie（不建会话表）：内容是 `用户编号.过期时间.签名`，签名覆盖用户编号、过期时间和密码哈希，所以改密码自动让旧会话失效；停用的用户每次请求时查一次。
- 后端新增提取器 `CurrentUser`（用户编号、角色），所有接口从它取身份；账户相关的 SQL 一律带 `user_id = $n` 条件，找不到时返回 404（不区分「不存在」和「不是你的」）。管理员接口用 `AdminOnly` 提取器，普通用户调用返回 403。
- 登录失败限速：同一用户名连续 5 次失败后锁 5 分钟，防止猜密码。
- 自选股改为按用户保存，现有的自选股归第一个管理员。

## 五、账户、风格与持仓

### 5.1 账户

账户有：名字（例如「华泰主账户」）、风格、现金、交易费率（佣金率默认万分之 2.5、最低 5 元；印花税按国家税率，不可改）、备注。每个用户最多 10 个账户。

### 5.2 风格

风格是一组预先定好的规则（代码中的常量，和策略模板一样），包括参考哪些策略、最多持几只、单只最多占多少、留多少现金、止损线、弱市时怎么办、追高上限。建账户时用三张卡片选择：

| | 保守 | 稳健（默认） | 进取 |
| --- | --- | --- | --- |
| 一句话 | 只跟随已经走稳的上涨趋势，宁可少赚也要少亏 | 跟随趋势，也接受刚刚启动的突破 | 追逐强势股和突破，波动大、可能大赚也可能大亏 |
| 参考的策略 | 趋势确认的均线金叉、均线多头、缩量回踩 20 日均线 | 保守的三个，加放量突破、MACD 金叉、回踩 20 日均线 | 稳健的六个，加创 60 日新高、强势股回调、Supertrend 趋势跟随 |
| 最多持有 | 5 只 | 6 只 | 8 只 |
| 单只最多占总资产 | 20% | 25% | 30% |
| 至少留现金 | 20% | 10% | 0 |
| 止损（相对成本价） | 亏 6% | 亏 8% | 亏 10% |
| 趋势卖出 | 收盘跌破 20 日均线 | 收盘跌破 20 日均线 | 收盘跌破 60 日均线 |
| 最长持有 | 不限（由趋势卖出控制） | 不限 | 不限 |
| 弱市（全市场站上 20 日均线的股票不到 30%） | 不买新股票 | 新买入的金额减半 | 照常 |
| 追高上限（第二天开盘比参考价高多少就不买） | 3% | 5% | 7% |
| 只采纳过去表现好于随便买的策略 | 是 | 是 | 否 |

- 表中的数字是初始值，第 4 期用「风格回测」验证后再定，卡片上展示每个风格过去 3 年的回测结果（年化收益、最大回撤、同期沪深 300）。
- 高级设置里可以改每一项，改过的账户显示「自定义」。

**风格引用的策略不能被用户改坏。** 现在的模板会在第一次启动时复制成普通策略，用户可以随意改或删。风格要引用稳定的定义，所以新增「内置策略」：`app.strategy` 加一列 `builtin_key`，每个模板一行，程序启动时按模板内容同步（像 `datasets.yaml` 同步到 `ops.dataset` 一样），页面上只读、不能删，想改就「复制为我的策略」。内置策略总是参加巡检。原来复制出来的普通策略保持不变。

### 5.3 持仓

每只持仓有：代码、股数、成本价（可选）、买入日（可选）、来源（手动录入，或执行了某条买入建议，记下是哪个策略）。

录入方式，按省事程度排：
1. **执行建议**：在建议上点「已执行」，默认按建议的股数和参考价，可改成实际成交的股数和价格，保存后自动加减持仓和现金（含估算费用）。
2. **粘贴**：从券商 App 的持仓页复制文字粘贴进来，系统识别每行中的 6 位代码、股数和成本价，先给出预览表，确认后保存；识别不了的行标红让用户改。
3. **逐只添加**：搜索股票（复用 `SecuritySearch`），填股数，成本价和买入日可以不填。
4. **校准**：任何时候都能直接改持仓表和现金，改动记为一条「校准」流水。

**持仓的变化都记成流水**（`app.account_trade`）：买入、卖出、校准、转入转出现金、分红、送转。持仓表和现金是流水的结果，两者在同一个事务里更新。这样能回答「我的持仓为什么变成这样」，也能统计账户收益。

**分红送转自动记账：** 系统已经有公司行动数据（`mkt.corp_action`）。除权日开盘前，系统为持有这只股票的账户自动记一条流水：送转股按比例增加股数（不足 1 股舍去），现金分红按税前金额加到现金，成本价相应调整；流水上标明「系统根据公告自动记账」，建议页提示「分红税按持有时间扣，到账金额可能略少，可以校准」。

**多久没核对：** 持仓 10 个交易日没有任何变动、期间又有没执行的建议时，账户页提示「持仓可能和券商不一致，花一分钟核对一下」，带一个「和券商一致」按钮（只记核对时间）。

## 六、每日建议怎么生成

### 6.1 时机

```
同步运行结束 → 复权重算 → 每日巡检（已有） → 策略过去表现（每周或策略变化时重算） → 为每个账户生成建议
```

- 自动生成接在巡检之后（`sync/postprocess.rs` 中巡检的后面），失败只写日志，不影响同步。生成每个账户只需要读巡检结果和账户持仓股的日线，几百个账户也在几秒内完成。
- 建议的交易日是最新有日线的交易日 T，操作时间是下一个交易日 T+1。页面写清「根据 10 月 17 日收盘的数据，供 10 月 20 日（周一）开盘后操作」。
- 用户改了持仓、现金或风格后，这个账户的当天建议立即重新生成；旧的一份标为「已被新的一份取代」，不删除。
- 数据没有同步到最新交易日时，不生成新建议，页面写明「最新数据截至 X 日，今天的建议要等同步完成」。

### 6.2 生成步骤

生成是一个纯函数：输入是账户快照、风格参数、当天的巡检结果、策略过去表现、持仓股的日线和诊断、市场概况；输出是一份建议。同样的输入总是得到同样的输出，可以写单元测试逐条核对。

**第 1 步：给每只持仓下结论。** 按下面的顺序检查，命中第一条就定下动作：

| 顺序 | 规则 | 动作 | 理由示例 |
| --- | --- | --- | --- |
| 1 | 停牌 | 不动 | 停牌中，复牌后再判断 |
| 2 | 亏损超过止损线（有成本价时） | 卖出 | 收盘 13.80 元，比成本 15.10 元亏 8.6%，超过本账户的止损线 8% |
| 3 | 来自某策略的买入建议，且该策略的卖出条件今天满足 | 卖出 | 买入依据的「放量突破」策略的卖出条件「收盘跌破 20 日均线」今天满足 |
| 4 | 收盘跌破风格的趋势均线 | 卖出 | 收盘 13.80 元跌破 20 日均线 14.20 元，诊断的趋势是「偏弱」（均线空头排列） |
| 5 | 被 ST 或公告退市 | 卖出 | 10 月 15 日起被实施风险警示（ST），本账户不持有 ST 股 |
| 6 | 单只占总资产超过上限 | 减仓到上限 | 占总资产 31%，超过本账户的单只上限 25%，减到 25% |
| 7 | 以上都没有 | 继续拿 | 收盘仍在 20 日均线上方 3.2%；跌破 14.20 元（20 日均线）或亏到 13.89 元（止损价）时会建议卖出 |

- 没填成本价的持仓跳过第 2 条，页面提示「填上成本价才能按止损线判断」。
- 第 3 条只对执行建议买入的持仓有效；手动录入的持仓没有「买入依据」，用风格的通用规则（第 2、4、5、6 条）。
- 卖出数量是全部持股（含零股）；减仓按一手取整，减完后不足一手的零股留着。

**第 2 步：算出明天能用的钱。** 现金加上卖出、减仓估算回笼的钱（参考价 × 股数，扣佣金和印花税），减去风格要求保留的现金。A 股卖出的钱当天就能再买股票，所以卖出和买入可以在同一天完成。

**第 3 步：挑买入候选。**
1. 取风格参考的各个内置策略在交易日 T 的买点（`app.screen_hit` 中 `kind = 'buy'`），按股票合并，记下有哪几个策略同时选中。
2. 去掉已经持有的股票、今天在第 1 步被建议卖出的股票、ST 股。
3. 风格要求「只采纳过去表现好于随便买的策略」时，去掉只被不达标策略选中的股票（见 6.3）。
4. 排序：同时选中的策略数多的在前；一样多时，比策略过去 20 个交易日的平均超额收益；再一样时比成交额。排序规则写在页面上，每只股票显示「为什么排第 N」。

**第 4 步：分配资金。**
- 空余仓位 = 最多持有只数 − 第 1 步之后仍持有的只数。没有空余仓位或钱不够时，不买新股票，说明原因。
- 每只的目标金额 = min(可用资金 ÷ 空余仓位数, 总资产 × 单只上限)；弱市且风格为稳健时减半，保守时这一步直接跳过。
- 按交易规则取整：沪深主板、创业板一手 100 股；科创板至少 200 股、之后按 1 股递增；北交所至少 100 股、之后按 1 股递增。买入金额加估算佣金不超过目标金额。
- 不够买最小数量的跳过，写入「没选上的候选」，原因「钱不够买 1 手（需要约 ¥16,800）」。

**第 5 步：汇总。** 执行后预计的现金、持仓只数、各持仓占比，以及和风格上限的对比。卖出、买入都没有时，结论是「今天不用操作」，并说明原因（例如「4 只持仓都还在 20 日均线上方；今天没有符合本账户风格的新买点」）。

### 6.3 策略过去表现

为了让买入理由有数字支撑，系统定期为每个内置策略统计「过去 3 年在全市场的所有买点之后的表现」，用的就是巡检和 K 线上买卖点的同一套规则（`points::run`）：

- 买点次数、按策略卖出规则卖出时的平均收益、中间值、赚钱的比例、平均持有天数；
- 买点之后 5、10、20 个交易日的平均涨跌，和同期同一股票池「随便哪天买」的平均涨跌（与 [信号的过去表现](../domains/strategies.md#signal_stats) 的对比口径一致）；
- 超额收益 = 策略的平均涨跌 − 随便买的平均涨跌。超额为负的策略在保守、稳健风格下不采纳。

全市场 3 年的计算要十几秒，所以不在每天的巡检里做：每周的数据核检之后，或者策略的定义变了（定义哈希不同）、复权重算过时重算，结果存在 `app.strategy_stat`。建议里引用时写明统计的截止日期。

### 6.4 失效条件和挂单参考

- **买入：** 参考价是 T 日收盘价；「第二天开盘比参考价高 5% 以上（本账户的追高上限）就不要买」，给出具体价格；开盘一字涨停买不进时，这条建议作废，不顺延。止损价 = 参考价 × (1 − 止损线)，并写「如果跌到止损价卖出，这笔大约亏 ¥1,180，占账户总资产 0.5%」。
- **卖出：** 参考价是 T 日收盘价；一字跌停卖不出时，下一份建议里会继续出现，并注明「已连续 2 天建议卖出」。
- **继续拿：** 写出会让结论变成卖出的价格（趋势均线、止损价中较高的那个）。

## 七、建议的理由怎么写

每条建议的结构：

```json
{
  "key": "sell:000858.SZ",
  "action": "sell",
  "thscode": "000858.SZ",
  "name": "五粮液",
  "shares": 200,
  "ref_price": 138.00,
  "amount": 27600.00,
  "fee": 20.70,
  "headline": "收盘跌破 20 日均线，趋势转弱",
  "rule": {"id": "trend_exit", "text": "本账户（稳健）的规则：收盘跌破 20 日均线就卖出"},
  "evidence": [
    {"kind": "price", "text": "收盘 138.00 元，20 日均线 141.30 元，低了 2.3%"},
    {"kind": "diagnosis", "text": "趋势偏弱：5 日、20 日、60 日均线空头排列"},
    {"kind": "position", "text": "成本 142.50 元，买入 23 个交易日，亏 3.2%（¥900）"}
  ],
  "cautions": [
    {"kind": "diagnosis", "text": "RSI(14) 为 27，已经超卖，短期可能反弹"}
  ],
  "invalidation": "明天开盘一字跌停卖不出时，下一份建议会继续提示",
  "links": {"chart": "/securities/000858.SZ?overlay=ma:20,ma:60"}
}
```

- `headline` 是一句话结论，列表里只显示它；点开才看 `rule`、`evidence`、`cautions`。
- `rule` 是产生这个动作的规则原文和阈值；`evidence` 是支持的数字；`cautions` 是反面的信息，有就必须显示。
- 买入建议的 `evidence` 至少包括：选中它的策略和命中的条件（巡检的 `reasons`）、每个策略的过去表现和超额、诊断四个维度、市场环境；`cautions` 包括 RSI 超买、处在 60 日区间顶部、近 20 日涨幅过大、成交额偏小等。
- 文字全部由后端按规则生成（和策略的「白话说明」一样），前端只负责展示，保证同一个数字在各处说法一致。

建议页上的一条买入，展开后大致是：

```
🟢 买入 隆基绿能 601012.SH  200 股  参考价 79.00 元  约 ¥15,800（含费用）
   放量突破 + MACD 金叉，两个策略同时选中，排第 1

   为什么买
   · 「放量突破」：当天收盘创 20 日新高，成交量是 5 日平均的 2.3 倍
   · 「MACD 金叉」：当天 MACD 上穿信号线
   · 这两个策略过去 3 年在全市场各出现 3,412 次、2,087 次买点，
     20 个交易日后平均涨 2.4%、1.9%，同期随便买平均涨 0.6%
   · 诊断：趋势偏强（均线多头排列），量能偏强（放量上涨）
   · 市场：全市场 58% 的股票站上 20 日均线，不算弱市

   需要注意
   · 近 20 个交易日已经涨了 18%，处在 60 日区间的 92% 位置

   怎么做
   · 明天开盘高于 82.95 元（比参考价高 5%）就不要买
   · 止损价 74.26 元：跌到这里会建议卖出，这笔最多亏约 ¥950，占账户 0.4%

   [ 看 K 线和策略买卖点 ]          [ 已执行 ]  [ 不做 ]
```

页面底部固定一段：「没选上的候选」（最多 5 只，各带原因）和「建议只是根据规则和历史数据的参考，不保证收益」。

## 八、页面

- **登录页**：只有用户名、密码，没有注册入口。
- **用户页（管理员）** `/users`：用户列表、添加用户、重置密码、停用。
- **今日页**：顶部新增「我的账户」一栏，每个账户一行：名称、风格、总资产、今日涨跌、建议摘要（「卖 1 买 2」/「不用操作」/「等待同步」），点进建议页。没有账户时显示「建一个账户，每天收到调仓建议」。
- **账户列表** `/accounts`：卡片列出各账户的总资产、现金、持仓只数、今日盈亏、最近一份建议。
- **新建账户**（向导，三步）：① 名字；② 风格（三张卡片，默认稳健）；③ 现金和持仓（粘贴或逐只添加，可以先跳过）。完成后立即生成第一份建议。
- **账户页** `/accounts/:id`，三个标签：
  - **今日建议**（默认）：结论、清单、每条的「已执行 / 不做」、执行后预计、没选上的候选。
  - **持仓**：持仓表（现价、市值、占比、盈亏、离止损价和趋势均线还有多远），现金，校准、粘贴、加一只、转入转出现金。
  - **记录**：历史建议（每天一行，执行了几条）和流水；建议的事后表现（第 4 期）。
  - 设置（齿轮）：名字、风格、高级参数、费率、删除账户（需要输入账户名确认）。
- **我的**：改密码、退出。

## 九、数据模型

新增迁移，全部在 `app` schema：

```sql
CREATE TABLE app.user (
  user_id       BIGSERIAL PRIMARY KEY,
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,                       -- Argon2id
  role          TEXT NOT NULL CHECK (role IN ('admin', 'member')),
  disabled      BOOLEAN NOT NULL DEFAULT false,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  password_changed_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 自选股改为按用户保存
ALTER TABLE app.watchlist ADD COLUMN user_id BIGINT REFERENCES app.user (user_id) ON DELETE CASCADE;
-- 迁移时把现有行归第一个管理员，然后 SET NOT NULL，主键改为 (user_id, thscode)

ALTER TABLE app.strategy ADD COLUMN builtin_key TEXT UNIQUE;  -- 内置策略：对应模板，只读

CREATE TABLE app.account (
  account_id   BIGSERIAL PRIMARY KEY,
  user_id      BIGINT NOT NULL REFERENCES app.user (user_id) ON DELETE CASCADE,
  name         TEXT NOT NULL,
  style        TEXT NOT NULL CHECK (style IN ('conservative', 'balanced', 'aggressive')),
  overrides    JSONB NOT NULL DEFAULT '{}',          -- 高级设置中改过的参数
  cash         NUMERIC(18,2) NOT NULL CHECK (cash >= 0),
  commission_rate NUMERIC(8,6) NOT NULL DEFAULT 0.00025,
  min_commission  NUMERIC(8,2) NOT NULL DEFAULT 5,
  note         TEXT NOT NULL DEFAULT '',
  checked_at   TIMESTAMPTZ,                          -- 最近一次「和券商一致」
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, name)
);

CREATE TABLE app.position (
  account_id  BIGINT NOT NULL REFERENCES app.account (account_id) ON DELETE CASCADE,
  thscode     TEXT NOT NULL REFERENCES ref.security (thscode),
  shares      BIGINT NOT NULL CHECK (shares > 0),    -- 送转后可能有零股，不要求整手
  cost_price  NUMERIC(18,4),                         -- 每股成本（未复权），可空
  opened_on   DATE,                                  -- 买入日，可空
  strategy_id BIGINT REFERENCES app.strategy (strategy_id) ON DELETE SET NULL,  -- 买入依据
  PRIMARY KEY (account_id, thscode)
);

CREATE TABLE app.account_trade (
  trade_id    BIGSERIAL PRIMARY KEY,
  account_id  BIGINT NOT NULL REFERENCES app.account (account_id) ON DELETE CASCADE,
  kind        TEXT NOT NULL CHECK (kind IN ('buy', 'sell', 'dividend', 'bonus', 'cash_in', 'cash_out', 'adjust')),
  trade_date  DATE NOT NULL,
  thscode     TEXT,
  shares      BIGINT,                                -- 买入、送转为正，卖出为负
  price       NUMERIC(18,4),
  amount      NUMERIC(18,2) NOT NULL,                -- 对现金的影响，含费用
  fee         NUMERIC(18,2) NOT NULL DEFAULT 0,
  advice_id   BIGINT,                                -- 执行的是哪份建议的哪一条
  advice_key  TEXT,
  source      TEXT NOT NULL CHECK (source IN ('user', 'advice', 'corp_action')),
  note        TEXT NOT NULL DEFAULT '',
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX account_trade_idx ON app.account_trade (account_id, trade_id DESC);

CREATE TABLE app.advice (
  advice_id     BIGSERIAL PRIMARY KEY,
  account_id    BIGINT NOT NULL REFERENCES app.account (account_id) ON DELETE CASCADE,
  trade_date    DATE NOT NULL,                       -- 依据的收盘日
  superseded_by BIGINT REFERENCES app.advice (advice_id),
  rules_version INTEGER NOT NULL,                    -- 生成规则的版本，规则改了不改写历史
  input         JSONB NOT NULL,                      -- 现金、持仓、风格参数、市场概况、策略表现的快照
  result        JSONB NOT NULL,                      -- 结论、各条建议、执行后预计、没选上的候选
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX advice_current_idx ON app.advice (account_id, trade_date) WHERE superseded_by IS NULL;

CREATE TABLE app.advice_item_state (
  advice_id  BIGINT NOT NULL REFERENCES app.advice (advice_id) ON DELETE CASCADE,
  item_key   TEXT NOT NULL,                          -- 例：buy:601012.SH
  state      TEXT NOT NULL CHECK (state IN ('executed', 'skipped')),
  trade_id   BIGINT REFERENCES app.account_trade (trade_id) ON DELETE SET NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (advice_id, item_key)
);

CREATE TABLE app.strategy_stat (
  strategy_id     BIGINT PRIMARY KEY REFERENCES app.strategy (strategy_id) ON DELETE CASCADE,
  definition_hash TEXT NOT NULL,
  end_date        DATE NOT NULL,                     -- 统计截止日
  stats           JSONB NOT NULL,
  computed_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

- 金额用 `NUMERIC`，Rust 侧用 `rust_decimal`，不用浮点算钱；价格判断（均线、诊断）仍用现有的浮点计算。
- 建议的事后表现（第 4 期）不另建表：按 `result` 中的股票和 `trade_date` 从日线现算，结果可以缓存。

## 十二、边界情况

| 情况 | 处理 |
| --- | --- |
| 持仓停牌 | 「不动」，注明停牌；仍占一个持仓名额，市值按最近收盘价算 |
| 持仓退市 | 「卖出」并提示通过退市整理期或券商处理；已经没有行情时按最后收盘价算市值 |
| 持仓是 ST | 保守、稳健：卖出；进取：继续拿但在 `cautions` 提示 |
| 持仓不是股票（ETF、可转债） | 第一版只支持 A 股股票，录入时提示不支持 |
| 没填成本价 | 不判断止损，提示补填 |
| 现金为 0、仓位已满 | 只给持仓结论，买入部分写「仓位已满」或「没有可用的钱」 |
| 当天没有任何符合风格的买点 | 写「今天没有符合本账户风格的新买点」，列出没选上的候选（如果有）和原因 |
| 弱市 | 保守不买、稳健减半，写明今天的全市场比例和阈值 |
| 同一只股票，一个策略说卖、另一个说买 | 持有中：按第 1 步的规则顺序，卖出优先；没持有：不买，原因「已触发卖出规则」 |
| 用户在建议生成后才改持仓 | 立即重新生成，旧建议标为被取代，已执行的条目保留在流水中 |
| 一份建议几天都没执行 | 第二天的新建议从当前持仓重新算；同样的卖出注明「已连续 N 天建议卖出」 |
| 科创板、北交所 | 按各自的最小申报数量取整 |
| 同步失败、数据没到最新交易日 | 不生成，页面写明数据截至哪天 |
| 删除策略 | 内置策略不能删；建议里引用的策略名和数字都在快照中，历史建议照常显示 |

## 十三、分期实现

每一期都能单独发布、单独使用。

**第 1 期：多用户登录**
- 用户表、Argon2 密码、签名会话、`CurrentUser` / `AdminOnly`、登录限速、`niulai user reset-password`。
- 管理员的用户页、改密码页；自选股按用户。
- 验收：管理员添加的用户能登录、看不到同步和升级等管理功能；改密码后旧会话失效；已部署的系统升级后用原账号密码登录。

**第 2 期：账户与持仓**
- 账户、持仓、流水、粘贴识别、校准、转入转出、分红送转自动记账、账户页的持仓和记录标签。
- 验收：两个用户各自的账户互不可见；送转股之后持仓和成本自动正确；流水能解释每一次变化。

**第 3 期：每日建议**
- 内置策略、风格、策略过去表现、生成规则、理由、自动生成、建议页、今日页一栏、已执行 / 不做。
- 验收：每条建议都有规则、证据、需要注意（若有）、失效条件；点「已执行」后持仓、现金正确；规则用构造的行情逐条单元测试覆盖（止损、趋势卖出、减仓、弱市、取整、钱不够、追高）。

**第 4 期：验证与校准**
- 风格回测：把组合回测（`portfolio.rs`）扩展为「多个策略 + 风格规则」，在风格卡片上展示过去 3 年的结果，并据此校准第五节表格中的数字。
- 建议的事后表现：执行和没执行的建议之后 5、10、20 个交易日的涨跌。

## 十四、已经定下的问题

2026-10-17 用户确认：

1. **策略谁能改：** 只有管理员能改策略和信号，其他人只能查看和使用。
2. **管理员能不能看别人的账户：** 不能。每个用户只能看到自己的账户，管理员只管理账号本身。
3. **风格的参数：** 按第五节的初始值上线，每个账户可以在高级设置里自己改。
4. **证券范围：** 只支持 A 股股票，暂时不做 ETF、可转债等。
5. **用户：** 不开放注册，管理员在系统里添加用户、设置密码；第一个管理员来自环境变量；管理员可以把别人设为管理员、停用账号；新用户默认是普通用户。

四期都已按这些决定实现：登录见 [ADR：多用户登录与角色](../decisions/multi_user_login.md)，账户和建议见 [账户与调仓建议](../domains/accounts.md) 和 [ADR：账户的每日调仓建议](../decisions/account_advice.md)。实现时和本方案的差别以文档库为准：风格不再绑定策略、也不在建账户时选择，候选按有效策略的统一优先级排序，保守、稳健、进取只是高级设置里的参考值；持仓的卖出只看买入依据策略的卖出条件，不用它的止损和持有天数。

## 十五、不做的事

- 券商对接、自动下单、从券商自动读取持仓。
- 盘中实时建议：建议只按收盘数据，每天一份。
- 预测涨跌：建议只根据规则和已经发生的数据，页面不出现「预计涨多少」。
- 用户注册、找回密码邮件：用户由管理员添加，忘记密码由管理员重置。
