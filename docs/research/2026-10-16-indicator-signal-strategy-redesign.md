# 指标、信号、策略的重新设计

> 调研笔记，不属于 Project Doc 文档库。2026-10-16 写，在 [交接说明](2026-10-16-indicator-signal-strategy-handoff.md) 的基础上重新设计，供用户拍板后实现。

## 一、结论先说

1. **只有一种写法：条件。** 一个条件就是一句话：「A 比较 B」，A 是指标，B 是数或另一个指标，比较方式只有 6 种（高于、不低于、低于、不高于、上穿、下穿），外加一个时间范围（当天、最近 N 天内出现过、连续 N 天）。信号、策略的买入和卖出、诊断，全部用这一种写法。
2. **信号就是「起了名字的条件」。** 把一组常用条件存起来，起个名字，就是信号；不需要再学一套「规则类型」。用户自定义信号，就是用同一个条件编辑器写几条条件、起个名字。
3. **策略是买入条件加卖出条件。** 再加股票池和止损止盈。每天巡检给出三类结果：今日买点、今日卖点、持有中；同样的买卖点能画在个股 K 线上。
4. **让用户「感知」的关键不是更多说明文字，而是反馈。** 定义任何一个信号，马上能看到它在 K 线上标在哪里、今天哪些股票出现了、过去出现之后平均涨跌多少。用户正是靠这个反馈，把自己的认知变成能用的信号。
5. **复杂度的上限写死：** 条件只有一层「全部满足 / 任一满足」，不能嵌套；信号只能由指标组成，不能引用别的信号；指标是固定目录，不做公式语言。

交接说明中的分层（数据 → 指标 → 信号 → 策略 → 回测）保留；改动最大的是信号层：不再设计 6 种「规则类型」，而是复用策略里已经有的条件，只补一个「上穿 / 下穿」。

## 二、业内怎么做

| 产品 | 怎么组织 | 可借鉴的点 |
| --- | --- | --- |
| thinkorswim 的 Condition Wizard | 一个条件由「表达式 + 关系 + 表达式」组成，表达式可以是数值、指标（可调周期）、价格；关系是「高于」「上穿」这类可读的词；有偏移和「Within N 根 K 线内出现过」。多个条件只能整体选 Any 或 All，**要混合与或就得写 thinkScript** | 和我们现有的「比较条件 + 最近 N 天」几乎一样；一层与或、复杂的交给代码，是有意的复杂度上限 |
| TrendSpider | 告警、扫描、清单、策略回测**共用同一个可视化条件编辑器**；策略 = 入场条件 + 出场条件（条件、止盈、止损、移动止损、持有根数、入场条件失效）；收盘判断、下一根开盘成交；回测结果以箭头画在图上。还区分「触发条件」（只成立一两根）和「过滤条件」（持续成立） | 同一种条件写法用在所有地方；买卖点画在图上；「触发 / 过滤」就是我们的「事件 / 状态」 |
| StockCharts | 约 80 个预设扫描，所有人可用；会员可以把预设扫描载入工作台改参数（例如把「放量」从 4 倍改成 5 倍）；预设结果里隐含一个最低成交量过滤 | 「预设 → 复制改参数 → 自己写」三级阶梯；隐藏的默认过滤就是我们的股票池 |
| TradingView 选股器 | 预设筛选 + 可调参数的筛选器；完全自定义要写 Pine Script | 同样是「预设 + 调参数 + 代码」的阶梯 |
| Finviz | 下拉框式的筛选器，分描述、基本面、技术三组 | 使用者常犯的错误是一次叠十个条件，结果为零，所以要实时显示「现在能选出几只」 |
| 通达信 | 公式管理器写公式（例如跳空 `L>REF(H,1)`），条件选股调用公式；可以存成动态板块 | 表达能力最强，但要学一门语言，不适合我们的用户 |
| 同花顺问财 | 一句话选股（「量比 > 2，涨幅 < 5%」），也有条件组合界面和策略回测 | 自然语言可以作为以后「帮用户写条件」的入口，但底层仍是结构化条件 |
| Composer | 拖拽积木，有 If/Else 和 Any/All；评测普遍认为嵌套多了上手很难 | 嵌套是认知成本的主要来源 |

共同规律：

1. **一种条件写法，到处复用。** 扫描、告警、策略的入场和出场都是同一个编辑器。用户学一次就会用所有功能。
2. **三级阶梯：用预设 → 改参数 / 复制一份改 → 写代码。** 绝大多数用户停在前两级；第三级（代码）只给专业用户。
3. **可视化编辑器刻意只做一层与或。** 超出这个范围就进入代码。
4. **结果画在图上。** 信号的触发点、策略的买卖点都以箭头标在 K 线上，用户靠看图理解规则。

## 三、现在的问题

已核实的事实（补充交接说明第 2 节）：

| 问题 | 事实 |
| --- | --- |
| 两套写法 | 策略条件是 JSON（信号条件 + 比较条件）；信号是 `signals.rs` 里一个 25 个分支的 `match`。同样是「5 日均线上穿 20 日均线」，信号能写，策略的比较条件写不出来，因为比较只有 `> ≥ < ≤`，没有「上穿」 |
| 信号不能自定义 | 新增信号要改 Rust 代码；用户唯一能调的是信号的参数 |
| 看不到信号在哪 | K 线图只能画两条均线和它们的金叉死叉；其余 24 个信号、全部指标都不能画在图上 |
| 不知道信号好不好 | 没有任何「出现之后表现如何」的数据，用户无法判断一个信号是否值得用 |
| 买卖点不完整 | 卖出规则只在回测中生效；巡检只给「今天入选」，没有卖点和持有中 |
| 诊断是另一套规则 | 四个维度的阈值写死在 `diagnosis.rs`，和信号、策略不通 |
| 入口分散 | 指标和信号在「说明」页，策略在「策略」页，数据在「数据」页，三者之间没有链接 |

交接说明中需要修正的地方：

- 信号层设计了 6 种「规则类型」（上穿下穿、越过阈值、比较、区间极值、连续、内置）。其中前 5 种都能写成「A 比较 B + 时间范围」：越过阈值就是「RSI 上穿 30」，区间极值就是「收盘价高于前 60 日最高收盘价」，连续就是时间范围里的「连续 N 天」。单独设计规则类型，等于让用户再学一套概念。
- 数据层不需要新建目录页。「数据」页已经有分类、中文名和说明，只要补上「能在条件里用的有哪些」。
- 信号的历史表现放在最后一个阶段太晚。它是用户判断「我的想法对不对」的唯一依据，应该和信号页一起做。

## 四、设计

### 4.1 用户只需要理解四个词

| 词 | 白话 | 例子 |
| --- | --- | --- |
| 指标 | 每只股票每天的一个数 | 20 日均线、RSI（14）、量比、市盈率 |
| 条件 | 一句话的判断，结果是「是」或「否」 | 「RSI（14）上穿 30」「收盘价高于 60 日均线」 |
| 信号 | 起了名字的条件，可以是几条条件同时满足 | 「均线多头排列」=「5 日均线高于 20 日均线」并且「20 日均线高于 60 日均线」 |
| 策略 | 什么时候买、什么时候卖 | 买入：出现「放量突破」；卖出：出现「跌破 20 日均线」，或亏损 8% |

回测不是新概念，是策略的一个按钮：「这个策略过去表现如何」。

### 4.2 条件：唯一的写法

```
条件 = 左边  比较  右边  [时间范围]
左边 = 指标（可调周期）
比较 = 高于 | 不低于 | 低于 | 不高于 | 上穿 | 下穿
右边 = 数 | 指标 | 信号（只在策略里可用，此时没有比较，直接写「出现 X」）
时间范围 = 当天（默认）| 最近 N 天内出现过 | 连续 N 天
```

- 「上穿」「下穿」沿用 `ma::cross_signals` 的容差规则，所以用条件重写的均线金叉和现在的结果逐位一致。
- 「连续 N 天」覆盖连续涨停、连续 N 天站在均线上方这类写法。
- 条件编辑器给每个指标配好「常用写法」（例如 RSI：低于 30、高于 70、上穿 30），点一下就填好，用户不必知道阈值。

### 4.3 信号

```
信号 = 名称 + 偏多或偏空 + 条件列表（全部满足 | 任一满足）+ 一句说明
```

- 25 个内置信号中，19 个直接用条件重写（金叉死叉、站上跌破均线、MACD、KDJ、RSI、布林带、新高新低、放量、大阳线、多头空头排列）。为此新增一个指标「前 N 日最高 / 最低收盘（不含当天）」，新高新低用它表达。
- 其余 6 个保留为「特殊信号」，逻辑在代码里，页面上照常显示：涨停、跌停、炸板、连续涨停（依赖涨跌停价推算）、向上跳空、长下影线（依赖前一天或 K 线形状）。
- 内置信号只读，可以「复制一份改」；自定义信号保存在新表 `app.signal`，可以改名、改条件、删除。删除前提示「有几个策略在用」。
- 信号只能由指标组成，不能引用别的信号。这样任何信号最多两层（信号 → 指标），点开就能看懂。
- 已保存策略里的 `signal` 名称（例如 `ma_cross_up`）保持不变，旧策略不用迁移。

### 4.4 策略

```
策略 = 股票池 + 买入（条件列表，全部 | 任一）+ 卖出（条件列表，任一）+ 止损 / 止盈 / 最长持有 + 排序
```

- 结构和现在的 `Definition` 基本相同，只是卖出规则不再只服务回测。
- **买卖点按单只股票计算：** 空仓时满足买入就记一次买点，持有中再出现买点忽略；持有时满足任一卖出规则就记一次卖点。收盘判断，第二个交易日开盘价成交，和现有回测一致。
- **每日巡检给出三类结果：** 今日买点、今日卖点（带原因，例如「跌破 20 日均线」）、持有中（持有几天、涨跌多少）。「今日」页显示每个策略的今日买点和卖点。
- **个股页可以选一个策略**，在 K 线上标出历次买点和卖点，和单只股票回测同一份计算。

### 4.5 指标

- 目录保持固定（现在 29 个，加上新增的「前 N 日最高 / 最低收盘」），不做公式语言。用户的「自定义」体现在选指标、调周期、写条件上。
- 每个指标页显示：是什么、怎么算（输入是前复权收盘价等，MACD 写明 12、26、9）、常用写法（可点击，直接新建信号）、在一只股票 K 线上画出来、被哪些信号和策略用到。
- **可以考虑的扩展：** 估值（市盈率、市净率）和流通市值已经每天同步，接成指标很便宜，用户可以写「市盈率低于 20」。限制是这些数据从 2026-10-15 才开始积累，只能用于选股，不能回测。是否现在加，需要用户决定。

### 4.6 反馈：让用户看见规则在做什么

这是「让用户感知」的核心，每个信号和策略都提供：

| 反馈 | 内容 | 实现 |
| --- | --- | --- |
| 在图上 | 个股 K 线上标出信号的每一次触发、策略的每一次买卖点；指标可以画在 K 线下方 | 后端按单只股票计算，前端画标记，和现在的金叉死叉标记同一种做法 |
| 今天 | 今天全市场有哪些股票满足 | 已有（预览接口） |
| 过去表现 | 过去 3 年全市场每次出现后 5、10、20 个交易日的平均涨跌和上涨比例，并和同期全部股票的平均对比 | 用组合回测同样的全市场逐只扫描，按需计算并缓存；3 年约几秒 |
| 被谁用 | 这个指标被哪些信号用、这个信号被哪些策略用 | 从定义中推算 |

「过去表现」只是统计描述，页面上写明「不代表以后」。

### 4.7 页面

```
今日   策略 ▾                        自选
       ├ 我的策略（列表、详情、编辑器）
       ├ 信号（内置 + 我的，表格：名称、一句话定义、偏多偏空、今天出现、过去表现）
       └ 指标（按分组，带常用写法）
```

- 信号和指标从「说明」页搬到「策略」下面：它们是搭策略用的积木，放在用的地方。「说明」页只保留三个概念的白话介绍，旧链接 `/guide#sig-*`、`/guide?tab=indicators#ind-*` 跳到新页面。
- 「数据」页（同步页）每个数据集加一行「用在：个股日线 → 所有价格类指标」；没接入指标的写「暂未用于选股」。
- 一条完整的路径：在信号页看到「放量突破」→ 点开看它在茅台 K 线上标在哪、过去表现如何 → 「复制一份改」把倍数从 2 改成 3 → 看过去表现有没有变好 → 「用它新建策略」→ 加卖出规则 → 回测 → 开启巡检 → 第二天在「今日」看到买点。

### 4.8 复杂度的边界

| 允许 | 不做 | 原因 |
| --- | --- | --- |
| 一层「全部 / 任一」 | 嵌套的与或 | thinkorswim 的可视化编辑器同样只做一层；嵌套是认知成本的主要来源 |
| 信号由指标组成 | 信号引用信号 | 保证任何信号点开就能看懂 |
| 固定的指标目录，可调周期 | 公式语言（通达信、Pine 那种） | 用户要先学语言；我们的用户不写代码 |
| 6 种比较 + 3 种时间范围 | 偏移任意天、跨周期 | 需要时以「新增指标」的方式补，例如「前 N 日最高收盘」 |
| 买卖点、止损止盈、持有天数 | 仓位、加减仓、资金分配 | 和交接说明 D2、D3 一致，资金只在组合回测里设置 |

以后真的需要更强的表达时，优先「新增指标」，其次「自然语言帮用户生成条件」（类似问财，底层仍是结构化条件），最后才考虑公式语言。

## 五、分阶段

| 阶段 | 内容 | 用户能感知到的变化 |
| --- | --- | --- |
| 1 | 信号页、指标页搬到「策略」下；K 线上画任意信号的触发点和任意指标；信号的过去表现；「被谁用」 | 能看见每个信号在图上标在哪、好不好用 |
| 2 | 条件加「上穿 / 下穿」「连续 N 天」；内置信号用条件重写（19 个，结果逐位一致）；自定义信号（复制改、新建、删除） | 能把自己的想法变成信号 |
| 3 | 策略买卖点：巡检输出今日买点、卖点、持有中；个股 K 线上画策略买卖点；「今日」页显示买卖点 | 策略从「选股」变成「什么时候买、什么时候卖」 |
| 4（可选） | 估值、流通市值接成指标 | 能写基本面条件，只用于选股 |

阶段 1 不改计算逻辑，风险最低，用户马上能感知；阶段 2 是自定义的基础；阶段 3 依赖阶段 2 的统一条件。

## 六、需要用户决定

1. **信号 = 起了名字的条件**（本文的设计），还是交接说明中的 6 种规则类型？建议前者：少一个概念，信号和策略用同一个编辑器。
2. **不做公式语言**，自定义只到「选指标、调周期、写条件」这一级？建议是。
3. **估值和流通市值接成指标**，现在做还是以后？现在做的代价是这些条件不能回测。
4. 持有中又出现买点时忽略、第二天开盘价成交，和现有回测保持一致？建议是。
