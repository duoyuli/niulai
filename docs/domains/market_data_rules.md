# 行情数据规则

本文说明本项目对行情数据的处理规则：时间戳换算、交易日、证券的上市与退市、停牌、快照与历史接口的精度差异，以及数据覆盖范围的限制。复权见 [复权](price_adjustment.md)，接口本身的约定见 [同花顺接口](../interfaces/hithink_api.md)。

<a id="timestamps"></a>
## 时间戳

供应商用毫秒 Unix 时间戳表示日期，含义是「Asia/Shanghai 当地零点」。换算规则：

- 毫秒时间戳转交易日：先加 8 小时，再加 1 小时，然后取日期。Rust 端是 `time::ms_to_cn_date`，数据库端是 `ops.ms_to_cn_date`，两者结果一致。
- 多加 1 小时是为了 1986–1991 年：那几年中国实行夏令时，当地零点按固定 +8 小时换算会落在前一天 23:00。例如 `673110000000` 应换算为 1991-05-02。
- 交易日转请求窗口：起点是当天 00:00（`cn_date_start_ms`），终点是当天 23:59:59.999（`cn_date_end_ms`），都按 +8 小时计算。1992 年以后没有夏令时，这样做没有误差。

**请求窗口的起点必须是零点。** 如果起点带上了一天中的某个时刻，当天的 K 线会被排除在窗口外。验证阶段曾因此漏掉了 2005 年以后上市的 2,863 只股票的上市首日。

<a id="trading_days"></a>
## 交易日

- 供应商交易日历（`a_share.calendar`）固定返回最近一年，写入 `ref.trading_day` 时 `source = api`。
- 更早的交易日在运行结束后从 `mkt.stock_bar_1d` 和 `mkt.etf_bar_1d` 中出现过的日期推导，`source = derived`。
- 规划 `trading_day` 分区时，使用 `ref.trading_day` 中的日期；早于已知最早日期的区间，退回到周一到周五。所以这类数据集排在交易日历之后的波次规划，见 [波次规划](../architecture/sync_pipeline.md#waves)；执行前还会再确认一次日期，见 [过期的日期](../architecture/sync_pipeline.md#stale_dates)。
- 交易日校验遇到本地日历里没有的日期时，会先刷新供应商日历，见 [交易日校验](#trade_date_guard)。
- 定时调度在触发时现取一次日历，用来判断今天是否为交易日，见 [定时调度](../architecture/sync_pipeline.md#scheduling)。

<a id="security_lifecycle"></a>
## 证券的上市、退市与 ST

- **代码表只有在市证券**：供应商的代码表和历史接口都查不到已退市股票，历史接口对它们返回 `1002 Unknown thscode`。用本库数据回测会有幸存者偏差。
- **退市推断**：每次同步 A 股代码表，如果本次列表超过 3,000 只，`last_seen` 早于今天、且尚未标记退市的证券，会被标记 `delisted_on = last_seen + 1`。列表过短时不推断，防止接口异常导致误判。证券重新出现时清除 `delisted_on`。
- **未上市的新股**：代码表中有上市日为空或在未来的股票（2026-10-15 有 5 只）。规划日线任务时跳过上市日在未来的股票；上市日为空的股票会规划请求，返回空结果，任务记为 `empty`。
- **日线窗口从上市日开始**：`a_share.bar_1d` 的第一个窗口起点是 `max(2005-01-01, 上市日)`。
- **ST 状态**：供应商没有历史 ST 状态。`ref.security_name_hist` 记录简称的变化区间，简称包含 `ST` 时 `is_st` 为 true，所以 ST 历史从开始采集的那天起积累。股票池过滤用的还是 `ref.security` 里的**当前**简称，历史 ST 状态仍然不可知。涨跌停不受这个限制：内部判断以供应商的涨停、跌停、炸板名单为准，名单从 2020-07-22（涨停）和 2025-10-16（跌停、炸板）起覆盖，见 [涨跌停](strategies.md#limits)。
- **涨跌幅限制的变化**：交易所规则本身也会变。供应商涨停池的数据显示，**2026-07-06 起主板 ST 的涨跌幅限制从 5% 变成 10%**。内部自算规则固定按 5% 算，所以有名单的日期一律以名单为准，自算只用于名单没有覆盖的日期。
- **停牌**：停牌日供应商不返回 K 线，`mkt.stock_bar_1d` 中也没有这一天的行；快照里停牌股的成交量为 0，不会写入。不要把缺失的日期当作采集失败，也不要补零。

<a id="snapshot_precision"></a>
## 快照与历史接口

当天的日线有两个来源：

| 来源 | 数据集 | 精度 | 写入时机 |
| --- | --- | --- | --- |
| 收盘快照 | `a_share.snapshot` | 开高低收与历史接口完全一致；成交量和成交额只保留约 9 位有效数字（例如 4,043,592,351.66 返回为 4,043,592,400） | 每个交易日收盘后 |
| 历史接口 | `a_share.bar_1d` | 精确 | 首次全量回补；之后每周一次，从游标往前重叠 10 天重取 |

写入规则（`mkt.stock_bar_1d.source`）：
- 快照写入的行标为 `snapshot`，同时写入交易所前收 `pre_close`。快照的前收在除权日与上一日收盘价不同，是交易所调整过的值。
- 历史接口写入的行标为 `hist`，覆盖同一天的 `snapshot` 行。
- 快照只会更新 `snapshot` 行的价格和成交量；已有 `hist` 行时只补 `pre_close`，不覆盖精确值。
- 快照中成交量为 0 或开盘价为 0 的股票（停牌）不写入。

ETF 日线（`mkt.etf_bar_1d`）同样有两个来源：收盘快照 `fund.market_snapshot`（`source = snapshot`，`price_basis = market_snapshot`，同时写入前收）和历史日线 `fund.etf_bar_1d`（`source = hist`，`price_basis = vendor_forward_adjusted`，供应商前复权价）。覆盖规则与股票相同：历史行覆盖同一天的快照行，快照只更新快照行、已有历史行时只补 `pre_close`，开盘价为 0 的不写入。实现见 `backend/src/sync/sinks.rs`。

<a id="trade_date_guard"></a>
### 交易日校验

快照类接口只返回「当前」的数据，响应中的 `data.timestamp` 是请求时刻，不是数据所属的交易日。例如 2026-10-16 00:06 请求快照，`data.timestamp` 是 00:06，价格却是 10-15 的收盘价。所以不能用 `data.timestamp` 判断数据属于哪一天。

配置了 `trade_date_guard: true` 的数据集（`a_share.snapshot`、`index.snapshot`、`a_share.valuation`、`a_share.auction_final`、`special.anomaly_reason`、`fund.market_snapshot`），执行前按以下规则判断：

| 情况 | 处理 |
| --- | --- |
| 运行交易日在未来，或不是交易日 | 跳过（`skipped`）。本地日历里没有这一天时，先刷新一次供应商日历；日历已经覆盖到这一天却没有它，或者是周末，才判定不是交易日。日历还没覆盖到这一天时（例如当天凌晨供应商日历还没更新）不据此判定，继续按下面的规则用供应商最新日线判断：供应商已有更晚的日线、日历里又没有这一天的，是节假日 |
| 运行交易日是今天，且上海时间早于 15:30 | 推迟：任务放回队列，10 分钟后再执行，不计入尝试次数 |
| 供应商最新交易日早于运行交易日（当天数据尚未就绪） | 推迟 |
| 供应商最新交易日等于运行交易日 | 执行 |
| 供应商最新交易日晚于运行交易日（这一天已经错过） | 记为失败（`dead`），错误信息以「已错过」开头，在同步页显示。只有当天值的数据从此补不回来；收盘快照、指数快照由日线补，见 [完整性核对与兜底补偿](../architecture/sync_pipeline.md#audit) |

「供应商最新交易日」取上证指数（`000001.SH`）最新一根日线的日期，每个执行者缓存 10 分钟。这样手动在开盘前或盘中发起运行时，不会把前一天或盘中的数据记成当天的收盘数据。

这些数据集只有当天的值，错过的交易日以后无法补回，所以它们每天执行，而且增量任务排在历史回补之前，见 [任务生命周期](../architecture/sync_pipeline.md#task_lifecycle)。

已核对的就绪时间：2026-10-15 19:14，历史接口和快照都已有当天的最终数据；最早几点可用尚未测试。数据未就绪时任务会每 10 分钟重查一次，直到就绪。

<a id="bad_rows"></a>
### 供应商的错误行

历史接口偶尔返回明显错误的一行。例如 000066.SZ 2006-09-25 的成交额是 9.2e18（接近 64 位整数上限）、成交量 1.8e14 股，写入时数值溢出，整个 10 年窗口的 2,317 行都写不进去。个股日线的写入规则：成交量或成交额达到 1e13 的行丢掉，同一窗口的其他日子照常写入；单只股票一天的成交额远不到这个数。

指数的基日那一行（点位 1000）没有成交量和成交额，按 0 写入。

<a id="coverage_limits"></a>
## 覆盖范围限制

| 数据 | 限制 |
| --- | --- |
| 个股日线 | 最早到 2005-01-04；只有开高低收、成交量（股）、成交额（元），没有前收（快照除外）、换手率、停牌行 |
| 指数日线 | 只有 2022-01-04 以后的数据；请求窗口起点早于这一天时直接返回空，不报错 |
| 公司行动 | 最早到 1991 年；逐只 REST 接口没有配股字段 |
| 股本与市值 | 没有总股本、流通股本；流通市值只能从集合竞价终态 `a_share.auction_final` 每天积累，可推算流通股本和换手率 |
| 估值、指数成分、异动原因 | 只有当前值，必须每天积累 |
| 退市股票 | 没有 |
| 涨停、跌停、炸板名单 | 涨停 2020-07-22 起、跌停和炸板 2025-10-16 起；没有北交所；涨停池每天有 1 行 `thscode` 为空。见 [数据目录](../interfaces/dataset_catalog.md#special) |

各数据集的完整范围见 [数据目录](../interfaces/dataset_catalog.md)。
