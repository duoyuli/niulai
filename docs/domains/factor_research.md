# 因子研究

本文说明横截面因子研究的口径：因子目录与取值、数据的时点规则、因子检验的统计量、挑选偏差的估计，以及多因子组合回测的交易规则。代码在 `backend/src/analysis/factors.rs`（因子目录与逐只证券的取值）、`factor_lab.rs`（读取面板、检验、组合模拟）、`research.rs`（Deflated Sharpe、PBO）、`fundamentals.rs`（财报的数据集 ID，与个股基本面接口共用）和 `research_run.rs`（一次研究运行：类型化配置、执行、运行记录和试验次数），接口在 `backend/src/api/research.rs`（只把查询参数转换成配置），页面是 `/research`。为什么从单只股票的买卖信号转向横截面因子，见 [ADR：用横截面因子研究检验选股方法](../decisions/cross_sectional_factors.md)。

<a id="service_scope"></a>
## 服务边界与调用链

因子研究是 `niulai serve` 内的一个功能，不是独立服务。它用于检验横截面排名和模拟定期持有股票，不连接券商、不下单、不修改账户持仓。证券和账户支持 ETF，但这里的面板只纳入 `AssetType::Stock`，不支持 ETF 组合研究、分钟行情、做空成交、整手撮合或旧策略回测。

| 阶段 | 入口与职责 | 数据和副作用 |
| --- | --- | --- |
| 请求 | `/research` 页面，或 `/api/v1/research/factors`、`/api/v1/research/factor-test`、`/api/v1/research/factor-portfolio` | 普通用户和管理员均需登录 Cookie；这是同步 HTTP 请求，不返回后台任务 ID |
| 参数 | `backend/src/api/research.rs` 校验参数并建立 `FactorConfig` | 不合法返回 400；默认值和范围见 [REST API](../interfaces/rest_api.md#endpoints) |
| 运行 | `research_run.rs` 调用 `compute::run(Budget::Foreground)` | 每进程最多 2 个前台全市场计算，后台另有 1 个槽位；超过时排队，不进入 `ops.task` |
| 输入 | `factor_lab::load` 读取交易日历、股票元数据、当前行业、日线和按需读取的财报 | `ref.trading_day`、证券表、`ref.index_member`、`mkt.v_analysis_bar`、三张财报在 `raw.record` 中的记录；不在研究请求中调用供应商 |
| 计算与返回 | `evaluate` 或 `simulate`，随后构建 `manifest` 并写入运行摘要 | 返回 `config`、`manifest` 和展开在顶层的结果字段；写入失败时不会返回成功，见 [运行记录](#run_record) |

PostgreSQL 是必需依赖；数据由同一服务的同步模块准备。Redis 只加速部分市场页面，不缓存本次因子研究结果。研究可以在已有数据上运行而无需同步执行者在线，但 `/ready` 返回成功只证明数据库能执行查询，不证明日线、财报或复权数据完整。启动、停止和恢复统一见 [运维手册](../operations/runbook.md#local_setup)。

<a id="usage"></a>
## 启动与调用

前置条件：已按 [本地运行](../operations/runbook.md#local_setup) 或 [Docker 部署](../operations/runbook.md#server_install) 启动服务；完成 [登录与最小调用](../operations/runbook.md#api_smoke)，当前终端已有 `BASE_URL` 和 `COOKIE_JAR`；已安装 `curl`、`jq`。以下命令不会自动回补行情。

1. 先读取因子目录，确认登录和研究路由可用。

   ```bash
   curl --fail-with-body --silent --show-error \
     --cookie "$COOKIE_JAR" "$BASE_URL/api/v1/research/factors" | jq 'map(.id)'
   ```

   预期为 12 个因子 ID；目录来自代码，不依赖行情是否齐全。返回 401 时先重新登录，不要直接重试计算。

2. 在 `/research` 页面选日期并点击「开始计算」，或设置本地已有股票数据覆盖的 `START`、`END` 后调用组合接口。两者是 `YYYY-MM-DD`，不应直接照抄其他环境的区间；`end` 会解析为不晚于请求日期的本地最新日线日期，解析后的区间至少 60 个自然日、最多 `366 × 5` 天。

   ```bash
   : "${START:?请先设置本地股票数据覆盖的开始日期}"
   : "${END:?请先设置本地股票数据覆盖的结束日期}"
   RESULT_FILE=$(mktemp "${TMPDIR:-/tmp}/niulai-portfolio.XXXXXX")
   HEADER_FILE=$(mktemp "${TMPDIR:-/tmp}/niulai-headers.XXXXXX")
   curl --fail-with-body --silent --show-error --get \
     --cookie "$COOKIE_JAR" --dump-header "$HEADER_FILE" \
     --output "$RESULT_FILE" "$BASE_URL/api/v1/research/factor-portfolio" \
     --data-urlencode 'factors=reversal:1,idio_vol:0.5' \
     --data-urlencode "start=$START" --data-urlencode "end=$END" \
     --data-urlencode 'rebalance=20' --data-urlencode 'top_n=30' \
     --data-urlencode 'buffer=0.5' --data-urlencode 'capital=1000000'
   ```

   这是接口验收参数，不是投资建议。命令非零退出时先检查状态、`x-request-id` 和错误正文；不要把错误 JSON 当作研究结果，也不要配置自动重试。仅做因子检验时使用 `/api/v1/research/factor-test`，传 `factors=reversal,idio_vol`、`start`、`end`、`horizon=5`、`quantiles=5`，不传组合本金和成本。

3. 成功后核对实际生效的配置、数据范围和结果字段。

   ```bash
   jq '{config, manifest, summary, picks_date, thin_days,
        trade_count: (.trades | length)}' "$RESULT_FILE"
   jq -e '
     (.trades | type == "array") and
     ((.trades | map(.fee) | add // 0) as $fees |
       (($fees - .summary.fees) | fabs) < 0.000001)
   ' "$RESULT_FILE"
   ```

   HTTP 200 不保证有成交或统计显著。必须同时看 `thin_days`、`picks_date`、持仓数和检验的 `periods`。`trades`、净值曲线和最新排名不持久化，需保留完整响应；同时记录服务实际构建提交、调用参数和时间。源码部署工作树的 `git rev-parse HEAD` 不能代替另一台机器上正在运行的镜像版本。

4. 完成后按 [退出与清理](../operations/runbook.md#api_smoke) 清理登录 Cookie。临时响应不含登录 Cookie，但可能含研究结果；归档后删除不再需要的 `RESULT_FILE`、`HEADER_FILE`。

<a id="catalog"></a>
## 因子目录

因子是每只股票每天的一个数，用来在同一天的全市场股票之间排名。`higher_is_better` 是目录中固定的预期方向，不保证之后的收益：为真时实现按数值越大越好处理。合成和分组时先按它统一方向，所以 RankIC 为正表示该区间的结果符合这个约定。

| ID | 名称 | 取值 | 预期方向 |
| --- | --- | --- | --- |
| `reversal` | 短期反转 | 过去 5 个交易日涨跌幅的相反数 | 越大越好 |
| `momentum` | 20 日动量 | 过去 20 个交易日涨跌幅 | 越小越好（A 股短期反转） |
| `momentum12m` | 12-1 月动量 | 250 个交易日前到 20 个交易日前的涨跌幅 | 越小越好（多数研究不显著，保留对照） |
| `volatility` | 波动率 | 过去 20 个交易日日收益率的标准差（0.02 约等于每天涨跌 2% 的幅度） | 越小越好 |
| `idio_vol` | 特质波动率 | 过去 20 个交易日个股日收益对全市场等权日收益做一元回归（扣掉随大盘涨跌的部分），残差的标准差 | 越小越好 |
| `max_return` | 最大日涨幅 | 过去 20 个交易日中最大的单日涨幅 | 越小越好（彩票效应） |
| `liquidity` | 成交额（规模代理） | 过去 20 个交易日平均成交额的对数 | 越小越好（小盘溢价，含壳价值） |
| `abnormal_turnover` | 异常成交 | 近 5 日与近 120 日平均成交额之比的对数 | 越小越好 |
| `illiquidity` | 非流动性 | 过去 20 个交易日每亿元成交额对应的平均绝对涨跌幅（Amihud 指标） | 越大越好 |
| `roe` | 净资产收益率 | 最近四个季度归母净利润 ÷ 最新股东权益（ROE，TTM） | 越大越好 |
| `profit_growth` | 单季利润增速 | 最新单季归母净利润相对去年同季的增长率，截在 ±1000% | 越大越好 |
| `accruals` | 应计利润 | 最近四个季度（归母净利润 − 经营现金流）÷ 总资产 | 越小越好 |

价量因子只用当天及以前的前复权日线，单元测试 `price_factors_only_look_back` 用截断的日线逐个核对；这不等于原始数据从未被修订。当前目录由 `GET /api/v1/research/factors` 返回，旧策略目录接口已经删除，见 [ADR：只保留多因子选股](../decisions/factor_only.md)。

## 数据与时点

一次计算通过 `prices::for_each_stock` 扫描日线，按 128 只证券分批读取。从读财报、行业和日线，到检验或组合模拟、写运行记录，整个运行持有同一个前台计算槽位，见 [限速与单一执行进程](../architecture/sync_pipeline.md#rate_limit)。开始日前额外读取按 270 个交易日换算的自然日窗口（`WARMUP_BARS = 260` 加 10）；这是预热余量，不保证每只证券都有 270 根日线。每根压缩日线 `CBar` 保存日历下标、前复权开收盘价和标记，只有取样日计算因子值。

- **交易日历：** 取自 `ref.trading_day`。某天有日线的股票不到区间中位数的一半时视为同步缺口（例如当天日线还没补完），这一天不取样、不成交，结果里的 `thin_days` 列出这些日期。
- **股票池：** `analysis::universe::Universe` 默认排除 ST、未复权收盘价低于 2 元、当日成交额不到 5000 万、本次加载窗口内截至当日日线不足 60 根的股票；日期达到已知退市日后排除，退市日前有数据的历史仍可参与。`min_listed_days` 的实现是日线根数，不是按真实上市日计算的完整交易日龄。可以用 `boards` 限定 `main`、`chinext`、`star`、`bse`。账户排名复用这个股票池类型。ST 按历史简称判断，没有历史时回退当前简称。
- **剔除小盘股：** `exclude_small_pct` 在每个取样日按 20 日平均成交额剔除最小的一部分。Liu、Stambaugh、Yuan 的 CH-3 模型剔除市值最小的 30%，因为这部分股票的价格里含有借壳上市的壳价值；本地没有历史股本，用成交额代替市值。
- **市场收益：** `finish` 对每只股票相邻两根有效日线计算前复权收盘收益，前一根日线属于股票池时，将收益计入后一根日线日期，再等权平均。停牌期间不逐日补零，跨停牌的收益集中在恢复日线那天；因此不能严格表述为「前一交易日全部在池股票的日收益」。特质波动率和组合基准共用该序列，不使用指数日线。
- **行业：** 中性化只读 `ref.index_member.valid_to IS NULL` 的同花顺行业成分，每只股票取当前成分最多的行业，数量相同时按指数代码排序。数据库可以积累成分区间，但研究加载器没有按历史日期读取；「通常二级、约 90 个行业」是旧样本描述，不是代码保证。
- **财务因子的可用日：** `a_share.income_q`、`balance_q`、`cashflow_q` 按年内累计值处理（Q2 是半年报）。`Report::deadline` 固定使用一季报 4 月 30 日、半年报 8 月 31 日、三季报 10 月 31 日、年报次年 4 月 30 日；`Report::available` 在利润表的报告日期不晚于该日时使用报告日期，否则回退到该日。程序没有验证真实首次披露、逾期披露或三张报表是否同日发布。可用日严格早于取样日才使用；TTM 和单季值由累计值换算，依赖各期的可用日取最晚值，最新报告期超过实现中的 15 个月窗口时视为没有财务数据。旧文提到「2025 年半年报的日期后来变成 2026-08-14」的供应商样本本轮未重取，不能据此保证所有报告均满足该推断。

## 因子检验

`GET /api/v1/research/factor-test` 按持有期 `horizon`（5、10、20 个交易日）取样，每隔 `horizon` 个交易日取一次横截面。正常成交时计划持有窗口不重叠；延期卖出可能跨入后续窗口，固定间隔也不能保证样本独立或消除所有统计偏差。

1. **预处理：** 每个取样日、每个因子先截尾到中位数 ± 3 倍稳健标准差（1.4826 × MAD），再标准化。选择中性化（默认）时，对行业哑变量和规模（20 日平均成交额的对数）回归取残差：按 Frisch–Waugh 定理，等价于因子和规模都先减去行业均值，再对规模做一元回归。规模因子本身只做行业中性化；中性化后几乎没有剩余变化的那一期视为没有信息，不再把浮点误差放大成排序。
2. **前向收益：** 取样日收盘决定，下一个交易日开盘买入，持有期结束后的开盘卖出，用前复权价。买入日停牌或一字涨停的股票不计入；卖出日一字跌停顺延到下一根能卖的日线；之后再没有日线时按最后收盘价。收益不含交易成本。
3. **统计量：** 对每个因子或合成列分别计算；一个取样日同时有有效因子值和前向收益的股票少于 50 只时，跳过该列的该期。存在完整持有窗口但各列都没有足够样本时仍可返回 200，`periods` 为 0，不应把空统计量当成有效结论。

| 字段 | 含义 |
| --- | --- |
| `rank_ic_mean`、`rank_icir`、`rank_ic_t` | 因子排名与前向收益排名的相关系数（Spearman）的均值、均值 ÷ 标准差、均值的 t 值 |
| `hit_rate` | RankIC 为正的期数占比 |
| `quantile_returns`、`quantile_annual` | 按因子分组（默认 5 组，第一组是预期最差）后各组每期平均收益和年化 |
| `long_short_annual`、`long_short_t`、`long_short_sharpe` | 最好一组减最差一组的年化收益、t 值和年化 Sharpe |
| `top_excess_annual` | 最好一组相对股票池平均的年化超额 |
| `top_turnover` | 最好一组每期换掉的比例；越高交易成本越大 |
| `monotonicity` | 组序号与组收益的秩相关；1 表示从最差组到最好组单调上升 |
| `decay` | 同一批取样日上持有 1、5、10、20 日的 RankIC；持有期越长仍然高，说明可以少调仓 |
| `correlation` | 因子之间的平均横截面秩相关（方向已统一） |

两个以上因子时额外检验「等权合成」：各因子统一方向后的标准化值取平均（至少一半因子有值），再标准化。

4. **显著性：** 结论按 RankIC 的 t 值给出。Harvey、Liu、Zhu（2016）统计了几百个已发表的因子，建议新因子 t ≥ 3 才算显著：试的因子越多，偶然显著的越多。`significant` 为真要求方向与预期一致且 t ≥ 3。
5. **挑选偏差：** 把本次每个候选（各因子和合成的多空每期收益）对齐到共同的取样日。
   - **PBO：** 回测过拟合概率，Bailey、Borwein、López de Prado、Zhu（2015）的组合对称交叉验证（CSCV）。把时间切成 8 段（期数不到 32 时切 4 段），枚举一半做样本内、一半做样本外的全部组合，统计样本内 Sharpe 最高的候选在样本外排到后一半的比例。高于 50% 说明是在挑噪声。
   - **Deflated Sharpe：** Bailey、López de Prado（2014）。Sharpe 最高的候选在扣除「从 N 个里挑最好的」带来的期望最大值、并考虑收益的偏度和峰度之后，真实 Sharpe 大于 0 的概率。N 是本次的候选数，方差取各候选每期 Sharpe 的方差。通常要求高于 95%。

<a id="run_record"></a>
## 运行记录和试验次数

**运行记录和试验次数。** 方法定义是 `research_run::FactorConfig`：决定结果的全部参数，即因子和权重、中性化、剔除小市值比例、完整的股票池条件、持有期或调仓间隔、检验的分组数，组合回测的持有只数、缓冲区、本金和交易成本；不含日期区间。配置哈希由它派生，同一个定义算一次试验，换了其中任何一个参数就是另一组配置。每次运行写入 `ops.backtest_run`：`mode`（`factor_test` 或 `factor_portfolio`）、日期区间、配置哈希、完整配置（`config`）、运行清单（当时的数据版本、覆盖范围、已知偏差）和结果摘要。`manifest.trial_count` 是同一种研究按配置哈希去重后已经试过的组数（含这一次）。

两个研究 GET 接口都有写库副作用：计算完成后、返回成功之前插入运行记录；重复请求会新增一行，同一配置通常不增加去重后的试验数。计数覆盖整个数据库，不按用户或日期区间隔离，且统计与插入不在同一个串行事务里，并发运行不能把该值当作严格递增序号。目录 GET 不写运行记录。不要将计算接口用作探活，也不要因为网络响应丢失就假定没有写入。

组合只保存 `summary`，不保存 `trades`、`equity`、`rebalances`、`picks` 或完整响应；当前没有按运行 ID 读取这些明细的 API。`manifest.instruments` 和 `observed_bars` 是区间内原始股票日线的覆盖数，不是过滤后实际参与排名的数量。`derived_versions` 是生成清单时读取的版本标记，不是不可变行情快照；面板分批读取也不保证整个请求处于同一数据库快照。换数据、换代码或新增其他配置的试验后，重跑可能得到不同结果或不同的挑选偏差统计。

<a id="portfolio"></a>
## 多因子组合回测

`GET /api/v1/research/factor-portfolio` 从区间首个交易日起，每隔 `rebalance` 个交易日（默认 20，约一个月）在收盘时排名，下一个交易日开盘调仓；额外把区间最后一天纳入取样以生成最新排名。区间最长 5 年。账户按自然月末调仓且使用真实份额、现金和交易限制，不能把这里的结果当成账户流水重放。

- **打分：** 预处理同 [因子检验](#test)。各因子统一成「越大越好」后按 `factors` 里的权重加权平均（`reversal:1,idio_vol:0.5`，默认 1，负数表示反过来用），至少一半权重的因子有值才参与，再标准化。
- **目标持仓：** 已持有的股票排名还在 `top_n × (1 + buffer)` 以内时继续持有（缓冲区，默认 0.5），其余名额按排名补到 `top_n` 只（默认 30）。不在目标里的持仓卖出。
- **成交：** 先卖后买，前复权开盘价成交，滑点默认 10 基点、买卖各收一次。卖出遇到停牌、一字跌停顺延；已有待卖订单且本次加载序列中之后再没有日线时，按最近收盘价模拟了结，不计滑点和费用，不代表现实中一定能卖出。买入遇到停牌、一字涨停顺延，下一次成功形成目标持仓时取消旧买单并重新生成，取消数计入 `skipped_buys`。买入预算使用「卖出后的现金 + 保留持仓按最近收盘价估值」，不是全部持仓按当日开盘价重估；每只预算取该总值除以 `top_n` 与现金除以剩余待买只数的较小值，再留出佣金和过户费。允许零股，已持有的股票不再平衡到等权。
- **费用：** `analysis::costs::Costs`：佣金（默认万分之 2.5、最低 5 元）、过户费、卖出印花税（默认千分之 0.5），响应的 `costs` 原样回显。资金少、持有只数多时最低佣金会明显拖累：10 万分 30 只，每只约 3300 元，5 元最低佣金单边就是 15 基点，所以本金默认 100 万（1000 元到 100 亿）。
- **基准：** 名称是「全市场等权（含分红）」，使用 [市场收益序列](#data) 累乘，不额外扣基准交易费用；与组合使用同一次面板扫描。
- **指标：** `excess_annual` 是组合年化收益减基准年化收益。令 `active` 为逐日组合收益减基准收益，`tracking_error = std(active) × sqrt(252)`，`information_ratio = mean(active) / std(active) × sqrt(252)`，标准差使用样本标准差；信息比率不是 `excess_annual / tracking_error`。`turnover_annual` 是累计买入金额除以平均总资产，再除以 `summary.days / 252`。区间不足 90 个自然日时，组合与基准年化及 `excess_annual` 为空；零方差等不可计算值也可能为空，不应填成 0。
- **Deflated Sharpe：** 响应的 `deflated_sharpe` 用每日收益计算，试验次数是 `ops.backtest_run` 中 `mode = factor_portfolio` 按配置哈希去重后的组数（含这一次），方差取各组最近一次的每日 Sharpe 的方差。试得越多，同样的 Sharpe 打折越多。
- **最新得分：** `picks` 来自最近一次有效排名，日期在 `picks_date`。末日是 `thin_days` 或有效排名不足 `top_n` 时，会保留更早的结果；从未形成排名时为空。`held` 是该次排名时是否持有，不保证是期末持仓快照。账户不读取这个名单，而是通过 `factor_lab::ranking` 独立计算 [账户排名](accounts.md#ranking)。

### 调仓计划与成交记录

`rebalances` 的日期是收盘决策日，`buys`、`sells` 是计划数量，不是成交数量；最后一天的排名不追加调仓计划，因为区间内没有下一交易日可执行。实际模拟成交看 `trades`，按日期升序返回，同一天先卖出或了结、再买入，同一天同一方向不承诺证券顺序。买单顺延时记在实际模拟成交日，未成交的待买单不产生记录。

| 字段 | 当前含义和例外 |
| --- | --- |
| `side` | `buy`、`sell`、`liquidate`；后者只是序列结束时的模拟清算假设 |
| `price` | JSON 数字；买卖用含滑点的前复权开盘价，`liquidate` 用最近前复权收盘价，不另加滑点；都不是历史原价委托 |
| `amount`、`fee` | 金额不含费用，`liquidate.fee = 0`；各笔 `fee` 合计与 `summary.fees` 在浮点误差范围内一致 |
| `profit`、`profit_pct` | 买入为 `null`；卖出和了结的利润是 `amount - fee - 买入含费成本`，比例是利润除以买入含费成本，0.1 表示 10% |
| `held_days` | 买入为 `null`；其他方向为买入到退出的面板交易日下标差，不是自然日，也不是有日线的天数 |
| `thscode`、`name` | 证券代码及本次加载的名称；不是历史名称快照，名称缺失时为空字符串 |

区间结束时不强制平掉全部持仓，未退出部分没有卖出记录，盈亏体现在最终市值中，所以卖出利润合计不等于组合总利润。前端将 `trades` 倒序显示，「卖出」筛选包括 `liquidate`，见 [页面说明](../architecture/frontend.md#pages)。

因子检验按分组等权且不计成本，组合有持仓数量、缓冲区、延期和费用限制，两者不能直接互相验证收益大小。

### 历史测量（待确认）

原文记录了 2026 年 10 月的一次本地测量：2023-10 至 2026-10、五个价量因子等权、持有 30 只、每月调仓，不计成本年化超额约 7.9%，100 万本金计成本后约 4.2%；两周调仓时年换手由 11.5 倍升至 17 倍，超额接近被成本抵消。另记录了 release 构建下全市场 3 年组合约 20 秒、5 年检验约 20 至 30 秒，以及 5 年压缩日线约 90 MB（每根约 12 字节）。这些数字缺少完整的构建提交、数据快照、因子 ID、成本参数和机器规格，本轮未重算；只保留历史背景，不能作为当前收益结论、内存上限或性能验收值。

<a id="troubleshooting"></a>
## 错误与排查

先保存 HTTP 状态、错误正文、请求参数和 `x-request-id`，不要记录 Cookie、密码或供应商 Key。源码部署看前台输出，Docker 部署在部署目录执行 `docker compose logs --since 10m niulai`；日志配置见 [配置来源](../interfaces/configuration.md#sources)。

| 现象 | 核对与恢复 |
| --- | --- |
| 401 | Cookie 缺失、过期、用户停用或密码变更；重新完成登录，不能用供应商 API Key 或指标令牌代替登录 |
| 400「本地还没有日线」或「所选区间内没有日线」 | 核对日期、`ref.trading_day`、股票日线和证券元数据；只有 ETF 日线不满足研究面板。由管理员检查 `/sync`、首次回补和失败任务，数据准备好后重新发起 |
| 400 参数或区间错误 | 按 [API 参数](../interfaces/rest_api.md#endpoints) 修正。有效区间以解析后的结束日计算；研究参数越界会拒绝，不会自动截断 |
| 200 但没有成交、`picks` 为空或 `periods = 0` | 检查股票池过滤、因子预热、财报缺失、同步缺口和有效排名数量。组合至少需要 `top_n` 个有效排名；检验每列每期需要至少 50 对有效值。保留空结果含义，不人为填造数据 |
| `picks_date` 早于 `summary.end` | 最后一天未通过缺口或有效排名检查，展示的是较早排名；先排查数据，不把旧排名标成当日结果 |
| 请求等待、408 或客户端超时 | 先区分计算槽位排队、数据库查询和 CPU 计算；HTTP 默认 300 秒，数据库连接获取上限 10 秒、单条 SQL 上限 120 秒。减小区间或减少并行请求，排查日志后手动重试；不保证调高 HTTP 超时就能解决 SQL 超时 |
| 点击「取消」后服务仍忙 | 前端取消网络请求；`run_cpu` 是同步 CPU 段，没有逐步取消检查，不保证立即停止。没有服务端取消、进度查询或断点续算接口；重新计算是一次新运行 |
| 500 | 数据读取、计算编排或运行记录写入失败，详细原因在服务日志。恢复依赖后重新调用；响应中断不证明记录没有写入 |
| 普通用户保存或删除预设返回 403 | 当前中间件没有放行这两个写操作；预设页面与权限意图的分歧待确认，见 [因子预设](accounts.md#presets)。研究 GET 本身仍可使用 |

停机或重启不恢复半途的研究 HTTP 请求；同步任务的租约恢复不适用于研究计算。请求已写入的运行摘要保留，尚未保存的完整响应不能从摘要还原。探活、指标与日志的检查步骤见 [探活与告警](../operations/runbook.md#health_monitoring)。

<a id="limits"></a>
## 已知偏差

- **幸存者偏差：** 代码表不含开始采集之前就已退市的股票，这部分股票本地没有日线；结果偏乐观。运行清单（`RunManifest`）的 `bias` 写明了这一点。
- **行业用当前归属**，没有历史行业成分。
- **没有历史股本：** 规模用成交额代替，EP、BP 等估值因子暂时无法计算（`a_share.valuation` 只有每天累积的当天值）。
- **财务数据的值可能是之后修订过的：** 可用日按截止日推断，但记录被之后的报告覆盖时，值也可能是修订后的。
- **成交按开盘价：** 没有模拟开盘价附近成交量不足和冲击成本，滑点是固定基点。
