# ADR：界面按任务组织

- 状态：已采纳（accepted），2026-10-16；决策第 6 条中「说明集中在「指标与信号」页」已被 [ADR：信号是起了名字的条件](custom_signals.md) 取代，信号和指标各有自己的页面，放在「策略」下面。后来导航加了「账户」（见 [ADR：账户的每日调仓建议](account_advice.md)），2026-10-17 起导航项「今日」改名「首页」：页面的数据截至上一个收盘、账户建议给下一个交易日，「今日」两头都对不上；策略的「今日买点」「今日卖点」相应改为「最新买点」「最新卖点」。主导航现在是首页、账户、策略、自选四项。
- 相关文档：[前端](../architecture/frontend.md#pages)、[选股策略与诊断](../domains/strategies.md)、[回测](../domains/backtest.md)。

## 背景

前端最初每加一个后端功能就加一个页面：股票列表、自选、选股、均线扫描、回测、指数板块、数据同步，导航有 7 项。加入策略、巡检、诊断和组合回测之后，用户的反馈是「功能堆叠过多」「新功能没有体现出来」：

- 首页是 5,000 多只股票的分页列表，打开后看不到今天发生了什么。
- 「均线扫描」和「均线交叉」策略做的是同一件事。
- 回测是独立页面，要先选模式、再选股票或策略，而用户想回测时，通常正看着某个策略或某只股票。
- 每个页面把所有数字都摆出来（回测结果有 8 个指标卡，诊断有 6 个价位），用户分不清先看哪个。

使用者没有金融背景，主要做三件事：每天看一眼今天怎么样、用自己的方法选股并检验这个方法、看自己关注的股票。

## 决策

1. **主导航只有四项：首页、账户、策略、自选。** 个股不是导航项，从页头的搜索框进入。数据同步、指数板块、设置，以及指标与信号的说明放在页头右侧，不和日常任务并列。
2. **首页一页看完今天的情况。** 大盘涨跌、强势行业、每个策略今天选出的股票（新入选的在前）、自选股的最近信号，一页看完。
3. **回测是一个动作，放在对象上。** 策略页的「过去表现如何」是全市场组合回测，个股页的「回测」用均线交叉或任意策略回测这只股票。去掉独立的回测页。
4. **去掉股票列表和均线扫描页。** 找股票用搜索；找发生均线交叉的股票用「均线交叉」策略。旧地址跳转到新页面，接口保留。
5. **每页先给结论，再给少量数字。** 一句白话结论，最多四个关键数字；其余数字、明细表、口径选择和规则说明折叠起来。只在内容不同的时候列出明细，例如策略只有「全部满足」的条件时，结果表不再逐行重复同样的条件。
6. **解释放在用到的地方。** 信号和指标的说明集中在「指标与信号」页，文字来自后端目录（`description` 是什么，`usage` 怎么看）；页面上的信号标签、编辑器里的条件都链接到对应条目，不在每个页面重复写说明。

## 取舍

- **保留功能页、只加首页：** 不采用。导航还是 7 项，同一件事有两个入口。
- **把自选并进首页：** 不采用。首页只显示自选股的信号摘要，加减收藏和完整列表仍然需要一个页面。
- **组合回测自动计算：** 不采用。全市场回测需要几秒到十几秒，打开策略页就计算会让页面变慢，改为点「开始回测」后计算；单只股票回测只要几十毫秒，切换参数时自动计算。

## 后果

- 新功能先回答「用户在做哪件事时需要它」，放进对应页面的已有区域，不默认新增导航项或页面。
- 地址变化：`/screener` 改为 `/strategies`，`/backtest` 和 `/signals` 不再是页面。
- 板块强弱只在首页显示前几名，完整排名在指数与板块页。
