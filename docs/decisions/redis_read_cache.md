# ADR：Redis 共享读取缓存与页面预热

- 状态：已采纳（accepted），2026-10-20。
- 相关文档：[共享读取缓存与预热](../architecture/read_cache.md)、[配置](../interfaces/configuration.md)、[部署](../operations/runbook.md#deployment)。

## 背景

首页会同时请求市场概况、今日热点和板块排名。这些结果需要扫描全市场日线或读取多组原始记录，首次打开页面时会让多个请求同时计算。服务仍保持 PostgreSQL 为事实来源，且同一份服务可能有多个只提供 API 的进程，因此单纯的进程内缓存不能共享结果。

## 决策

1. 使用可选的 `REDIS_URL` 接入 Redis，只保存 JSON 页面结果；未配置或不可用时回退到进程内缓存和 PostgreSQL。
2. 缓存键包含派生数据版本、交易日和接口参数。复权因子或权威涨跌停池变化会切换版本，旧键通过 TTL 和 Redis 淘汰策略回收。
3. `niulai serve` 启动后台预热，每 5 分钟预热最新交易日的市场概况、行业和概念板块近 5 日排名、今日热点。预热失败不影响 API。
4. Redis 不参与同步限速、任务队列、登录会话、账户数据或 API Key 存储；这些边界继续由进程内组件或 PostgreSQL 负责。

## 取舍

- 共享缓存减少重复计算和多进程冷启动，但引入了一个可选运行时依赖；降级路径保留了单机开发和 Redis 故障时的可用性。
- 版本化键避免同步完成时遍历删除大量键，代价是旧结果会在 TTL 到期前短暂占用 Redis 空间。
- 预热只覆盖首页的固定组合，用户主动修改日期、板块类别或窗口时仍按需计算并回填。
