# ADR：指标在 Rust 中计算，扫描结果按复权版本缓存

- 状态：已采纳（accepted），2026-10-16。决策第 2 条中的因子表日期索引和第 4 条的默认扫描日期已被 [ADR：等比复权因子按区间存储](adj_factor_segments.md) 取代：因子表已删除，扫描默认取日线表的最新交易日。决策第 3 条的扫描缓存和全市场扫描接口 `GET /signals/ma-cross` 于 2026-10-17 删除（没有页面使用）；第 1 条「指标在 Rust 中计算」仍然有效。
- 相关文档：[均线与交叉信号](../domains/ma_signals.md)、[回测](../domains/backtest.md)、[运行结束后的计算](../architecture/sync_pipeline.md#postprocess)、[数据库分层](../architecture/data_model.md#ops_tables)。

## 背景

全市场均线扫描（`GET /signals/ma-cross`）每次请求约 4 秒，页面打开很慢。2026-10-16 用 `EXPLAIN ANALYZE` 拆解（约 1,500 万行日线、65 万行参与计算）：

| 环节 | 耗时 | 原因 |
| --- | --- | --- |
| 移动平均窗口函数 | 约 2.8 秒 | `avg(float8)` 没有反向转移函数，`ROWS n PRECEDING` 窗口每移动一天都要重新累加整个窗口 |
| 关联复权因子 | 约 1.3 秒 | `mkt.adj_factor_1d` 只有 `(thscode, trade_date)` 主键，日期条件不会传到因子表上，每次顺序扫描整张表 |
| 排序落盘与 JIT | 约 0.3 秒 | `work_mem` 只有 4MB，排序写临时文件；JIT 编译 0.25 秒 |

每次请求都从头计算，没有缓存。而同一组参数的结果只在复权因子重算后才会变化：回补期间约 30 分钟一次，日常每天一次。

接下来还要做回测，它和扫描、单股均线、自选股诊断都依赖同一套均线和交叉规则。这些规则分散在三个接口的 SQL 和 Rust 代码中，容易不一致。

## 决策

1. **SQL 只读价格，指标在 Rust 中计算。** 新模块 `backend/src/analysis/`：`prices` 读取前复权价，`ma` 计算均线和交叉，`scan` 做全市场扫描，`backtest` 做回测。四个接口共用 `ma::ma_cross`。均线用滑动窗口加补偿求和（Kahan），复杂度 O(n)。
2. **按日期范围读取两张大表。** 新增索引 `adj_factor_1d_date_idx (trade_date)`。扫描查询不经过视图，在日线表和因子表上都写日期条件，并在事务内关闭 JIT、把 `work_mem` 调到 64MB。
3. **扫描结果缓存在进程内。** 键是 (交易日, 快线, 慢线)，版本是 `ops.derived_version` 中 `adj_factor` 行的 `updated_at`，每次复权重算完成时更新。版本变化后旧结果不再命中；最多保留 64 组。
4. 扫描的默认日期从「日线表的最新日期」改为「最新一个有复权价的交易日」，避免新日线还没有复权因子时扫描结果几乎为空。

## 取舍

- **物化每日均线：** 不采用。快慢线周期由用户输入（2 到 250），无法预先算好所有组合，而且每次重算复权因子都要重写。
- **外部缓存（Redis）：** 暂不采用。只有一个 `niulai serve` 进程（见 [ADR：单进程服务](single_process_service.md)），进程内缓存已经够用，重启后第一次请求重新计算即可。
- **浮点误差：** Rust 的结果与 SQL `avg` 不逐位相同。实测四个日期的全市场扫描、三只股票的全历史均线，均线相对差不超过 7e-16，交叉信号完全相同，远小于交叉判定的容差 1e-9。

## 结果

2026-10-16 在同一台机器、同一份数据上测得：

| 请求 | 之前 | 之后 |
| --- | --- | --- |
| 全市场扫描，第一次 | 4.0–4.3 秒 | 0.33–0.54 秒 |
| 全市场扫描，命中缓存 | 4.0 秒 | 约 2 毫秒 |
| 单只股票全历史均线 | 约 29 毫秒 | 5–11 毫秒 |
| 单只股票十年回测 | — | 约 30 毫秒 |

## 后果

- 新增技术指标时，计算写在 `backend/src/analysis/`，不要在 SQL 里用窗口函数计算。
- 复权价的来源变化时（例如新增一种派生价格），要在重算完成后更新 `ops.derived_version`，否则缓存会返回旧结果。
- 已有复权因子的日线被修订（例如收盘后历史接口覆盖快照数据）时，复权价立即变化，但版本要等下一次重算才更新，扫描缓存最多滞后一个重算周期（回补期间 30 分钟）。
