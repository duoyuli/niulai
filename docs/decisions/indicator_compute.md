# ADR：指标和信号在 Rust 中计算

- 状态：已采纳（accepted），2026-10-16。
- 当前实现：[选股策略与诊断](../domains/strategies.md)、[回测](../domains/backtest.md) 和 [运行结束后的计算](../architecture/sync_pipeline.md#postprocess)。
- 历史取舍：早期的 SQL 全市场均线扫描、因子表日期索引和扫描专用缓存已经删除；复权因子存储见 [ADR：等比复权因子按区间存储](adj_factor_segments.md)。

## 决策

1. 指标、信号、买卖点和回测共享 `backend/src/analysis/` 中的 Rust 计算逻辑，避免同一规则在 SQL、API 和回测中出现不同实现。
2. 计算读取已经落库的行情和复权价格；停牌日不填充为零，数据不足的位置保持为空并按「条件不满足」处理。
3. 全市场巡检在同步完成后运行并保存结果。市场概况和信号统计可以使用进程内缓存，缓存版本由 `ops.derived_version` 中的复权因子和涨跌停池时间戳控制。
4. 新增指标或信号必须补充白话定义、公式、参数边界和单元测试；新增 API 时同步生成 OpenAPI 和前端客户端。

## 取舍

- Rust 计算便于复用和单元测试，但需要维护数值算法、预热长度和边界样本。
- 不预先物化所有周期的指标；周期范围由目录限制，按请求或巡检需要计算。
- 指标计算不单独引入 Redis 或独立计算服务；页面结果的共享读取缓存遵循 [ADR：Redis 共享读取缓存与页面预热](redis_read_cache.md)。只有出现可复现的吞吐、延迟或资源隔离问题时才重新评估计算服务边界。

## 结果

当前接口和页面不再提供旧的 `GET /signals/ma-cross` 全市场扫描端点。全市场策略结果保存在 `app.screen_run` 与 `app.screen_hit`，单只证券的指标、信号、买卖点和回测按同一套 Rust 规则计算。
