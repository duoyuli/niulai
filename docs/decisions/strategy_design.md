# ADR：选股策略使用 JSON 定义

- 状态：已被取代（superseded），2026-10-23，由 [ADR：只保留多因子选股](factor_only.md) 取代：选股策略、信号和巡检都已删除。下文只解释当时的取舍，不能作为开发依据。
- 原实现已删除，需要时看 git 历史。

## 背景

使用者希望用能读懂的条件组成策略，每天巡检全市场，并在个股和组合回测中复用同一套买卖规则。脚本和公式语言虽然表达力更强，但会提高学习、校验和解释成本。

## 决策

1. 指标、条件、信号和策略分层。指标提供数值，条件提供判断，信号为命名条件，策略由资产范围、买入条件、卖出规则和排序组成。
2. 策略保存在 `app.strategy.definition` 的 JSON 中，条件只支持目录中的指标、信号、自定义信号和有限的比较、时间范围组合；前端使用表单编辑，不开放脚本或公式语言。
3. 当前目录由代码提供：指标、信号和参数说明通过 API 暴露；具体数量和规则当时以策略领域文档与 `backend/src/analysis/` 为准。
4. 同步完成后运行全市场策略巡检，结果可在策略页、证券 K 线和账户建议中引用。单只回测与组合回测都使用策略定义，但交易价格、公司行动和组合约束的差异必须明确展示。
5. 内置模板同步为只读内置策略；用户需要修改时复制为普通策略。策略过去表现属于研究结果，不作为策略定义的一部分；账户是否启用历史表现过滤由账户规则决定。

## 取舍

- 不开放脚本、公式语言、因子打分和仓位程序，换取白话说明、结构校验和稳定的回测入口。
- 只保留一层「全部满足 / 任一满足」组合，限制表达能力以控制认知和测试成本。
- 组合回测使用适合全市场扫描的价格口径和组合近似；单只证券回测保留更细的交易规则。两者不能直接当作同一个成交模型。

## 后果

- 新增指标、信号或条件需要同步更新代码目录、白话说明、测试、OpenAPI 和前端生成客户端。
- 已保存的 JSON 必须向后兼容；新增字段提供默认值，删除字段需要迁移。
- 策略筛选结果、历史表现和账户建议分别记录，不能把统计结果写回策略定义或当作收益承诺。
