# ADR：选股策略是 JSON 定义，指标和信号用固定目录

- 状态：已采纳（accepted），2026-10-16；决策第 1 条和第 3 条已被 [ADR：信号是起了名字的条件](custom_signals.md) 取代。部分取代 [ADR：采用等比复权](equal_ratio_adjustment.md) 决策第 3 条：全市场组合回测的成交价和市值用前复权价。
- 相关文档：[选股策略与诊断](../domains/strategies.md)、[回测](../domains/backtest.md#portfolio)、[运行结束后的计算](../architecture/sync_pipeline.md#postprocess)。

## 背景

用户没有金融背景，希望「基于信号上的值设定一些动态策略，每天定时巡检，把达到策略的股票筛选出来」，并能检验这些策略过去的表现。之前只有一种信号（均线交叉死叉）和一种回测（单只股票的均线交叉）。

调研了 tick-stock-panel 等开源项目（笔记在 `docs/research/2026-10-16-tsp-signals-and-strategies.md`，不属于本库）。它们的指标和信号很全，但策略要写 Python 代码，概念也多（因子、打分、仓位管理、多种回测引擎），不适合这个用户。

## 决策

1. **只有三个概念：指标、信号、策略。** 指标是每天一个数，信号是某天发生的事或所处的状态，策略是资产池加一组条件。打分、权重、仓位管理不进入策略定义。
2. **策略是 JSON 定义，不是代码。策略只描述买入和卖出条件；按历史表现筛选属于账户规则，不写入策略定义。** 条件只有两种：信号在最近 N 天内出现过、一个指标和一个数值或另一个指标比较；用「全部满足」和「至少满足一个」两组组合。每条条件都能转换成一句白话，前端编辑器是表单，不需要写表达式。
3. **指标和信号用代码中的固定目录。** 29 个指标、25 个信号在 Rust 中实现，目录通过 `GET /strategies/catalog` 提供给前端。用户只能选择和调参数，不能自定义公式。
4. **巡检挂在同步运行结束之后。** 日线写入并重算复权后立即巡检，不另设定时任务；结果保存，便于比较「新入选」和查看历史。
5. **提供 10 个模板，第一次启动时复制为普通策略。** 「今日」和「策略」页一打开就有结果，用户从模板改起。
6. **全市场组合回测用资产各自的价格口径近似。** 逐只股票或 ETF 读入几年的日线；股票和 ETF 使用各自的行情事实与交易规则，组合回测允许零股。单只股票回测仍然用原价加公司行动事件，ETF 使用供应商前复权行情。

## 取舍

- **用户写表达式或脚本：** 不采用。表达能力最强，但用户写不出来，也难以校验和解释；以后需要时可以在 JSON 中增加一种条件。
- **策略打分排序：** 不采用。只按一个指标排序，结果容易解释；多因子打分需要先理解每个因子。
- **定时任务巡检：** 不采用。收盘数据到达的时间不固定，挂在同步运行之后，数据一到就巡检，也不会在数据不全时巡检。
- **组合回测按原价加事件逐笔处理：** 不采用。要为几千只股票分别读取和处理公司行动、按一手取整，耗时和代码复杂度都会成倍增加。前复权价的收益率与「分红再投资」的真实收益一致，误差主要来自零股和红利税，对比较策略好坏影响不大。

## 后果

- 新增信号或指标要改代码（`signals.rs`、`indicators.rs`）并发布；前端从目录自动生成选项，不用改。
- 策略定义的结构变化要兼容已保存的 JSON：新字段要有默认值。
- 组合回测与单只股票回测在同一只股票上的结果可能不同（零股、分红处理），文档和页面上都说明了。
- 强势板块过滤依赖当前成分股，回测中不生效。
