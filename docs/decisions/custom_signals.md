# ADR：信号是起了名字的条件，策略给出买卖点

- 状态：已采纳（accepted），2026-10-16。部分取代 [ADR：选股策略是 JSON 定义](strategy_design.md) 决策第 1 条（三个概念）和第 3 条（信号用固定目录），以及 [ADR：界面按任务组织](ui_by_task.md) 决策第 6 条中说明页的位置。2026-10-17 按调研笔记补充到 56 个内置信号（新增趋势强度、背离、更多 K 线形态，以及「中性」这种方向），决策本身不变，现状见 [信号](../domains/strategies.md#signals)。
- 相关文档：[选股策略与诊断](../domains/strategies.md)、[REST API](../interfaces/rest_api.md#endpoints)、[前端](../architecture/frontend.md)。

## 背景

上一版只有指标、信号、策略三个概念，信号是代码里的 25 个固定条目。用户反馈两点：一是看不懂信号到底怎么判断，像黑盒子；二是想按自己的想法调信号，例如把「放量」的倍数和「站上均线」合在一起，但只能在策略里一条条重复写。策略也只会选股，不告诉用户什么时候卖。

调研了同花顺问财、通达信公式、TradingView Pine、thinkorswim 的条件编辑器（笔记在 `docs/research/2026-10-16-indicator-signal-strategy-redesign.md`，不属于本库）。公式语言表达力最强但用户要先学语言；thinkorswim 的可视化编辑器只做一层与或，足够常见需求。

## 决策

1. **四个词：指标、条件、信号、策略。** 条件是「指标 比较 数或指标」加时间范围，或「出现某个信号」；信号是起了名字的条件；策略是买入条件加卖出规则。
2. **条件只有一种写法。** 比较 6 种（高于、不低于、低于、不高于、上穿、下穿），时间范围 3 种（当天、最近 N 天内出现过、连续 N 天），只有一层「全部 / 任一」。
3. **内置信号能写成条件的都用条件定义。** 25 个中 19 个改写，结果和旧实现逐位一致；涨跌停、跳空、长下影线 6 个保留为特殊信号，页面上写出规则。为此新增指标「前 N 日最高 / 最低收盘」。
4. **用户可以自定义信号，但信号不能引用自定义信号。** 自定义信号保存在 `app.signal`，可以复制内置信号后修改。任何信号最多两层（信号 → 指标或内置信号），点开就能看懂。
5. **卖出规则不再只服务回测。** 巡检按单只股票的买卖点给出今日买点、今日卖点和持有中，规则和回测一致：持有中出现买点忽略，次日开盘成交。
6. **每个信号和指标都能被看见。** 信号和指标各有一页，放在「策略」下面（搭策略用的积木，放在用的地方）：画在任意股票的 K 线上、今天出现在哪些股票、过去出现后的涨跌和同期所有股票对比、被哪些信号和策略用到。「说明」页只保留四个概念的介绍。

## 取舍

- **公式语言：** 不采用，理由同上一版。需要更强的表达时，优先新增指标，其次让自然语言帮用户生成结构化条件。
- **嵌套的与或、信号套信号：** 不采用。嵌套是理解成本的主要来源；需要组合时在策略里把几个信号放在一起。
- **估值指标（市盈率等）：** 暂不加。数据从 2026-10-15 才开始积累，只能选股不能回测。
- **持有中按真实持仓：** 不采用。没有交易记录，按规则从一年前推算，页面上写明不是实际持仓。

## 后果

- 已保存策略中的内置信号名称不变，旧策略不用迁移；`Condition` 新增 `my_signal` 和时间范围字段，都有默认值。
- 判断策略前要读出全部自定义信号（`signal_lib::load`），预览、巡检、回测、诊断都这样做。
- 巡检要从一年前推算买卖点，读入的日线和耗时都比只看当天多。
- 自定义信号改了定义，用到它的策略下一次巡检起按新定义，历史结果不重算；有策略在用时不能删除。
