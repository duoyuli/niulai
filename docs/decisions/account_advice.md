# ADR：账户的每日调仓建议

- 状态：已采纳（accepted），2026-10-17。
- 相关文档：[账户与调仓建议](../domains/accounts.md)、[选股策略与诊断](../domains/strategies.md)、[ADR：多用户登录与角色](multi_user_login.md)。调研和方案草稿在 `docs/research/2026-10-17-account-advice-design.md`。

## 背景

用户要在系统里建多个证券账户（不同券商、不同风格），记录资金和持仓，每天根据已有的策略和证券走势生成调仓建议。两个硬要求：用起来认知成本极低；建议有理有据，列清楚每件事背后的原因。当前支持 A 股股票和交易所 ETF；每个用户只看得到自己的账户，管理员也看不到；规则的参数可以设置。实现第一版后用户又要求：保守、稳健这些只是举例，不要和具体策略（例如趋势类）绑定，而是根据已有的策略用一套优先级算出好的证券；建账户时不选风格，三种风格放到高级设置里作为参考。

之前和其他 Agent 讨论的初版方案每次生成都要用户选策略、填持仓只数，持仓的「卖、留」直接用策略模拟的持有状态，理由只有一句命中的条件，执行后要重新录持仓。

## 决策

1. **规则不绑定策略，候选按统一的优先级排序。** 候选证券来自全部参加巡检的策略（或账户勾选的），勾选的策略都可提供候选，按「同时选中的勾选策略数 → 成交额」排序。账户的规则只管买入门槛、组合约束和可选保护线：至少几个策略、持几只、单只上限、留现金、弱市、追高，以及默认关闭的账户保护线。个股卖出由买入策略的完整卖出规则负责，账户不再设置趋势均线。历史回测数字不参与账户决策。建账户时用稳健型的默认值；保守型、稳健型、进取型只是设置页旁边的建议，讲组合设计，不展示回测数字。
2. **内置策略只读。** 账户默认参考全部参加巡检的策略，内置策略保证总有一批稳定、不会被改坏的策略可参考，所以每个模板一行内置策略，启动时按模板同步，不能改、不能删、总是巡检；想改就复制一份。原来第一次启动时把模板复制成普通策略的做法取消，没改过的复制品被接管为内置策略。
3. **持仓按用户自己的成本和买入日判断。** 每只绑定策略的持仓按该策略的完整卖出规则判断，账户保护线只有主动开启时才叠加，ST 和单只上限独立处理；没有绑定策略的手工持仓不会凭空套用趋势均线。策略模拟的持有状态和用户的真实买入无关，不用。
4. **生成是纯函数，输入原样保存。** 同样的输入总是同样的输出，每条规则用构造的数据单元测试；`app.advice.input` 保存当时的全部输入、`rules_version` 记规则版本，历史建议不随规则变化改写。
5. **理由结构化，由后端生成。** 每条建议有规则原文、支持的数字、反面信息（有就必须显示）、怎么做和失效条件；买入引用命中的策略和条件，不引用历史回测数字。前端只展示。
6. **执行即记账。** 点「已执行」（可改实际股数和价格）记一笔流水，持仓和现金跟着更新；分红送转按公告自动记账。流水是持仓和现金变化的唯一来源，校准也记流水。
7. **每天自动生成。** 巡检完成后为每个账户生成；用户已经处理过的那份不再自动重算，免得建议在手上变了；改了持仓或设置立即重算，旧的一份标记被取代。
8. **账户决策与研究回测分开。** 策略过去表现和账户回测保留为用户主动研究工具；它们不进入账户建议，账户建议也不因后台统计是否完成而改变。三组参考值只保留组合约束和保护线说明，不后台计算回测。

9. **买入前回看属于账户规则。** 账户可以按股票和策略选择多个历史周期与收益门槛；通过的策略才计入最少同时选中数。默认稳健型开启 1 年和 3 年、门槛大于 0；回看只影响买入，计算严格使用当日及以前数据。
10. **账户保护线默认关闭。** 保护线是账户主动开启的额外安全层，可能早于策略卖出；账户设置和建议理由必须明确显示其状态。账户趋势均线不再存在，想用均线卖出时直接写入策略的 `exit.any`。
11. **本次规则变更保留旧账户。** 升级迁移把旧账户规则中的 `stop_loss_pct` 转成可选的 `protection_stop_loss_pct`，保留账户、持仓、流水和建议；旧字段名在读取时继续兼容。旧的参考值回测属于派生结果，会清空并由用户主动研究时重算。

## 取舍

- **按历史表现筛选策略：** 不采用。历史数字会让用户先入为主地挑选已经涨过的策略；策略本身已经包含设计时的判断，勾选后就应参与。
- **让用户自己挑策略组合：** 不作为默认。认知成本高；保留在高级设置里，可以只勾选部分策略。
- **按信号强度、波动率分配仓位：** 暂不采用。等分加单只上限容易解释，用户一眼能核对。
- **盘中实时建议、对接券商：** 不做。只用收盘数据，每天一份；下单由用户自己在券商完成。
- **让后台回测决定账户是否买入：** 不采用。回测只作为用户主动研究工具。

## 后果

- 建议的候选取决于哪些策略当天命中。策略是全系统共用的库，管理员新增、改进策略后，所有账户的候选自动受益；历史回测数字不会改变是否参与。
- 新增的内置策略、规则参数、生成规则都要同步更新 [账户与调仓建议](../domains/accounts.md)，规则变化时加 `RULES_VERSION`。
