# ADR：账户的每日调仓建议

- 状态：已采纳（accepted），2026-10-17。
- 相关文档：[账户与调仓建议](../domains/accounts.md)、[选股策略与诊断](../domains/strategies.md)、[ADR：多用户登录与角色](multi_user_login.md)。调研和方案草稿在 `docs/research/2026-10-17-account-advice-design.md`。

## 背景

用户要在系统里建多个证券账户（不同券商、不同风格），记录资金和持仓，每天根据已有的策略和股票走势生成调仓建议。两个硬要求：用起来认知成本极低；建议有理有据，列清楚每件事背后的原因。用户还定下：只支持 A 股股票；每个用户只看得到自己的账户，管理员也看不到；风格的参数可以设置。

之前和其他 Agent 讨论的初版方案每次生成都要用户选策略、填持仓只数，持仓的「卖、留」直接用策略模拟的持有状态，理由只有一句命中的条件，执行后要重新录持仓。

## 决策

1. **用风格代替选策略。** 账户选保守、稳健、进取之一，风格是一组常量：参考的内置策略、最多持几只、单只上限、保留现金、止损、趋势均线、弱市处理、追高上限、是否只采纳好于随便买的策略。高级设置可以改每一项，只存和默认值不同的部分。
2. **内置策略只读。** 风格按模板 key 引用策略，用户改坏或删掉会让风格失效，所以每个模板一行内置策略，启动时按模板同步，不能改、不能删、总是巡检；想改就复制一份。原来第一次启动时把模板复制成普通策略的做法取消，没改过的复制品被接管为内置策略。
3. **持仓按用户自己的成本和买入日判断。** 每只持仓都有结论（止损、买入依据策略的卖出条件、趋势均线、ST、单只上限，按顺序），不存在「没有判断」的持仓；策略模拟的持有状态和用户的真实买入无关，不用。
4. **生成是纯函数，输入原样保存。** 同样的输入总是同样的输出，每条规则用构造的数据单元测试；`app.advice.input` 保存当时的全部输入、`rules_version` 记规则版本，历史建议不随规则变化改写。
5. **理由结构化，由后端生成。** 每条建议有规则原文、支持的数字、反面信息（有就必须显示）、怎么做和失效条件；买入引用策略过去 3 年全市场的表现和「随便买」的对比。前端只展示。
6. **执行即记账。** 点「已执行」（可改实际股数和价格）记一笔流水，持仓和现金跟着更新；分红送转按公告自动记账。流水是持仓和现金变化的唯一来源，校准也记流水。
7. **每天自动生成。** 巡检完成后为每个账户生成；用户已经处理过的那份不再自动重算，免得建议在手上变了；改了持仓或设置立即重算，旧的一份标记被取代。
8. **统计和回测每周算。** 策略过去表现和三种风格的回测要读全市场几年的日线，在后台每周算一次（定义变了也重算），建议和风格卡片读结果。

## 取舍

- **让用户自己挑策略组合：** 不采用作为默认。认知成本高，用户要先理解 14 个策略；保留在高级设置里。
- **按信号强度、波动率分配仓位：** 暂不采用。等分加单只上限容易解释，用户一眼能核对。
- **盘中实时建议、对接券商：** 不做。只用收盘数据，每天一份；下单由用户自己在券商完成。
- **建议回测时也用「好于随便买」筛选：** 不采用。那需要每一天之前的统计，否则是用未来的数据挑策略；回测中用全部参考策略，文档写明这个近似。

## 后果

- 风格的效果取决于参考的策略。2026-10-17 本地数据上，保守、稳健风格参考的趋势类策略过去 3 年买点之后 20 日的平均涨跌都不如随便买，统计出来后它们会被「好于随便买」筛掉，保守风格基本不会买入；三种风格的回测都明显跑输沪深 300。风格的组成需要按统计和回测重新选定。
- 新增的内置策略、风格参数、生成规则都要同步更新 [账户与调仓建议](../domains/accounts.md)，规则变化时加 `RULES_VERSION`。
