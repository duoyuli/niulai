# ADR：网页登录

- 状态：已采纳（accepted），2026-10-16。部分取代 [ADR：CI 构建镜像，部署只交付服务本身](ci_cd.md) 中「项目不包含登录」的决定。
- 相关文档：[登录](../interfaces/rest_api.md#auth)、[环境变量](../interfaces/configuration.md#settings)、[部署](../operations/runbook.md#deployment)。

## 背景

之前服务本身没有任何访问控制，只靠默认监听本机防止被别人打开。用户要求做一个简易的登录：配置一个 admin 账户和密码，打开网页先登录，登录状态在浏览器保存 30 天；没有配置时账号密码都默认为 `niulai`。

## 决策

1. **只有一个账户，来自环境变量。** `NIULAI_ADMIN_USER`、`NIULAI_ADMIN_PASSWORD`，默认都是 `niulai`。不做用户表、注册、改密码页面。
2. **后端统一拦截。** 中间件检查除健康检查和登录外的全部 `/api/v1/*` 接口；前端页面本身不拦截，收到 401 时转到登录页。
3. **登录状态是签名的 Cookie，不在服务端保存。** Cookie 中是到期时间和 HMAC-SHA256 签名，`HttpOnly`、`SameSite=Lax`，保存 30 天。签名内容包含账号和密码，签名密钥随机生成后保存在 `app.setting`。
4. **默认密码要提醒。** 仍在使用默认值时，启动日志和页面顶部都提示修改。

## 取舍

- **HTTP 基本认证：** 不采用。浏览器弹出的对话框不能说明是什么，也不能控制保存多久。
- **服务端会话表：** 不采用。只有一个账户，签名 Cookie 不需要建表和清理过期会话。代价是不能在服务端让某一个浏览器退出；要让所有浏览器都失效，修改密码并重启即可。
- **密码哈希存储：** 不采用。密码本来就以明文写在环境变量中，再做哈希没有增加安全性。
- **Cookie 加 `Secure`：** 不加。本项目不负责 HTTPS，通过 HTTP 访问时加了 `Secure` 就无法登录。

## 后果

- 部署后应修改默认密码；改账号或密码后，所有浏览器都要重新登录。
- 签名密钥在数据库中：恢复数据库备份后，登录状态跟着备份中的密钥走；删除 `app.setting` 中的 `session_secret` 可以让所有登录状态失效。
- 集成测试先登录再调用接口（`tests/integration.rs` 的 `logged_in`）。
