# ADR：用横截面因子研究检验选股方法

- 状态：已采纳（accepted），2026-10-23。决策第 1 条中「与策略、每日巡检、账户建议互不依赖」已由 [ADR：只保留多因子选股](factor_only.md) 改变：策略和巡检已删除，账户按因子排名调仓，排名复用因子研究的计算。
- 当前实现：[因子研究](../domains/factor_research.md)、[账户的因子排名](../domains/accounts.md#ranking)、[REST API](../interfaces/rest_api.md#endpoints)、前端 `/research`。

## 背景

2026-10-23 在本地数据上做了全市场组合回测（2023-10 至 2026-10，持有 10 只，滑点 10 基点）。5/20 金叉、创 60 日新高、强势股回调、首板接力、中期强势这五个模板的结果分别是 -64%、-82%、-83%、-99.9%、-97%；同期全市场等权基准是 +21%。把佣金、印花税和滑点全设成 0，「中期强势」前 18 个月仍然亏 87%，平均每笔 -4.1%。所以问题不在成本，而在信号本身的方向。

A 股的异象研究（Hsu 等、Jansen 等）发现，价格动量在 A 股为负，短期反转、低波动、特质波动率和彩票效应稳健为正。现有模板大多是突破、新高、按动量从高到低排序，系统性地买在短期过热的位置。在检验多重假设之后，简单技术规则在成熟市场基本找不到显著利润（White Reality Check、Hansen SPA 的研究）。

专业机构的做法是：每天给全市场股票打分排名，先用 RankIC、分组收益单独检验分数有没有预测力，再把有效的因子合成，定期持有得分最高的一批，并用 Deflated Sharpe、PBO 估计挑选偏差。

## 决策

1. 新增独立的因子研究：因子目录、因子检验（`GET /research/factor-test`）和多因子组合回测（`GET /research/factor-portfolio`），页面是策略栏目下的「因子研究」。它与策略、每日巡检、账户建议互不依赖。
2. 因子用横截面口径：每个取样日去极值、标准化，默认对行业和规模中性化，按 A 股研究的预期方向统一成「越大越好」。
3. 因子检验报告 RankIC、ICIR、t 值、分组收益、多空收益、换手和衰减；显著性按 Harvey、Liu、Zhu 的建议用 t ≥ 3。每次运行写入 `ops.backtest_run`，用配置哈希去重统计试过多少组，用于 Deflated Sharpe；同一次检验的多个候选用 CSCV 估计 PBO。
4. 财务因子按法定披露截止日推断可用日，不使用会被之后的报告覆盖的供应商报告日期。
5. 不改变已有策略的 JSON 定义和按策略选股的流程；因子研究的结果不作为选股的门槛（选股流程不展示也不使用回测数字的约定不变）。
6. 账户按因子排名每月调仓（见 [ADR：只保留多因子选股](factor_only.md)）。排名直接决定买卖，不读取任何回测、IC 或 Deflated Sharpe 数字；默认的因子组合来自研究记录，写死在代码里。

## 取舍

- 选择在现有日线和财报上实现，不引入 Python 或额外服务：与 [ADR：指标在 Rust 中计算](indicator_compute.md) 一致，一次全市场扫描在几十秒内算完。
- 没有历史股本，规模用成交额代替，EP、BP 等估值因子暂缓；需要供应商提供历史股本或市值后再加。
- 行业用当前归属，没有历史行业成分；中性化有轻微的前视偏差，行业很少变化，影响有限。
- 组合回测用前复权价、允许零股，不模拟分红记账和整手约束。
- 因子检验只支持 5、10、20 日的持有期，不做每日取样：每天取样会让计算量增大数倍，前后持有期重叠也会让 t 值虚高。

## 后果

- 新增因子要同时更新 `factors.rs` 的目录与取值、领域文档的目录表、单元测试（只看过去的检查）和生成的前端客户端。
- `ops.backtest_run.mode` 增加 `factor_test`、`factor_portfolio`（迁移 `20261023000001_factor_research.sql`）。
- 结果仍受幸存者偏差影响（本地没有开始采集之前退市的股票），页面和运行清单都写明了这一点。
