# ADR：多用户登录与角色

- 状态：已采纳（accepted），2026-10-17。取代 [ADR：网页登录](web_login.md) 的决策第 1、4 条和取舍中「密码哈希存储」一条；第 2、3 条（后端统一拦截、签名 Cookie）保留，签名内容改为用户编号和密码哈希。
- 相关文档：[登录与权限](../interfaces/rest_api.md#auth)、[环境变量](../interfaces/configuration.md#settings)、[数据库分层](../architecture/data_model.md#schemas)、[忘记密码](../operations/runbook.md#users)。

## 背景

用户要做「账户持仓与每日调仓建议」，每个人有自己的多个证券账户，互相看不到。原来的登录只有一个账号，来自环境变量，谁登录都是同一个人。用户的要求：

- 要有登录，每个用户只能看到自己的数据，管理员也看不到别人的账户。
- **不开放注册**，用户由管理员在系统里添加、设置密码。
- 环境变量里的账号密码写进第一个管理员；管理员可以把别人设为管理员、停用账号。如果大家默认都是管理员，有泄露风险。
- 策略只有管理员能改，其他人只能用。

## 决策

1. **用户存在数据库中**（`app.user`），密码用 Argon2id 哈希保存。用户名不区分大小写。没有注册接口，`POST /users` 只有管理员能调用。
2. **第一个管理员由迁移创建、还没有密码。** 启动时，如果它还没有密码，就用 `NIULAI_ADMIN_USER`、`NIULAI_ADMIN_PASSWORD`（默认都是 `niulai`）设置；之后这两个变量不再起作用，密码只在网页上改。已部署的系统升级后用原来的账号密码登录。
3. **两个角色。** 管理员：用户管理、数据同步、数据源设置、升级、修改策略和信号、手动巡检。普通用户：查看策略、信号、行情、指数，管理自己的数据（自选股，以后是账户）。新用户默认是普通用户，管理员权限要明确给。
4. **权限在一处判断。** 登录检查中间件按「角色 + 方法 + 路径」放行：管理员前缀（`/sync`、`/datasets`、`/setup`、`/users`、`/system/upgrade`、`/screening`）普通用户连查看都不行；普通用户的写操作只有白名单中的几个。新增接口默认不对普通用户开放写操作，忘了标注也不会放开。「我的」数据由接口按当前用户的编号过滤，别人的数据一律当作不存在。
5. **登录状态仍是签名 Cookie，不建会话表。** Cookie 是 `用户编号.到期时间.签名`，签名覆盖用户编号、到期时间和密码哈希。改密码、管理员重置密码后，这个用户之前的登录都失效；停用的用户每次请求都会被拒绝。
6. **防止把自己锁在外面。** 管理员不能修改自己的角色、不能停用自己、不能用重置接口改自己的密码（改自己的要输入现在的密码）；至少保留一个可以登录的管理员。都忘了时在服务器上执行 `niulai user reset-password <用户名>`。
7. **管理员设置的密码要提醒本人修改。** 管理员添加、重置的密码和默认密码都标记 `must_change_password`，本人登录后页面顶部提醒，改完后消失。
8. **猜密码要慢。** 同一用户名连续输错 5 次后暂停 5 分钟（进程内计数）；用户不存在时也做一次同样耗时的校验。

## 取舍

- **服务端会话表：** 仍不采用。签名覆盖密码哈希后，改密码就能让一个用户的全部登录失效，这是最常用的场景；每次请求查一次用户表，用户数很少，开销可以忽略。
- **每个用户自己的策略：** 不采用。策略、信号是全系统共用的库，由管理员维护；按用户区分要给策略、巡检结果都加归属，复杂度大增，用户也不需要。
- **管理员可以查看别人的账户：** 不采用。用户要求隐私，管理员只管账号本身。
- **邮件找回密码：** 不采用。没有邮件服务，用户都是管理员认识的人，由管理员重置。

## 后果

- 自选股按用户保存，迁移时把已有的归给第一个管理员。
- `NIULAI_ADMIN_USER`、`NIULAI_ADMIN_PASSWORD` 只在第一次启动时用一次，以后修改它们没有效果。
- 恢复数据库备份时，用户和密码跟着备份走。
