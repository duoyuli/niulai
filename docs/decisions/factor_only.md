# ADR：只保留多因子选股

- 状态：已采纳（accepted），2026-10-23；决策第 5 条中「账户里不能增删因子」已被 [ADR：账户里可以编辑因子](account_factor_editing.md) 取代。取代 [ADR：选股策略使用 JSON 定义](strategy_design.md)、[ADR：信号是起了名字的条件](custom_signals.md) 和 [ADR：账户的每日调仓建议](account_advice.md)，部分取代 [ADR：用横截面因子研究检验选股方法](cross_sectional_factors.md) 决策第 1 条和 [ADR：界面按任务组织](ui_by_task.md) 中「策略」导航项。
- 当前实现：[账户与调仓建议](../domains/accounts.md)、[因子研究](../domains/factor_research.md)、[REST API](../interfaces/rest_api.md#endpoints)、前端 `/accounts` 和 `/research`。

## 背景

2026-10-23 的研究（见 [研究记录](../research/2026-10-23-factor-strategy-research.md)）显示：原来的 21 个信号模板在 2023-10 至 2026-10 的全市场组合回测里全部大幅亏损，不计成本也亏；横截面因子在 A 股有稳定的预测力，组合 E（波动率、特质波动率、单季利润增速、应计利润、成交额五个因子等权，每月调仓，持有 30 只）在样本外跑赢全市场等权。账户随后加了「多因子月度调仓」作为第二种选股方式，和按策略买卖点选股并存。

用户试用后的反馈：页面上同时有指标、信号、策略、巡检、单股回测、规则回测和多因子几套东西，认知成本太高；以后只用多因子这一套，其余的都不要，也不要为旧数据做兼容，不留技术债。

## 决策

1. 选股只有一种方法：按账户规则里的因子给全市场排名，每月最后一个交易日收盘整体调仓，没有持满时每天补仓。账户规则只有因子和权重、持有只数、缓冲区、保留现金、追高上限和 ST 卖出六项，默认是组合 E。
2. 删除指标、信号（含自定义信号）、选股策略和内置模板、每日巡检、买卖点、个股诊断、均线交叉、信号的过去表现、单股回测、策略组合回测、滚动样本外验证、账户规则回测、买入前回看和稳健型、均衡型、积极型参考值，包括后端模块、接口、前端页面和文档。
3. 数据库用一个新迁移删除 `app.strategy`、`app.screen_run`、`app.screen_hit`、`app.signal`、`app.strategy_stat`、`app.preset_stat`，删除 `app.position.strategy_id`、`app.advice.rules_version` 和 `ops.backtest_run` 的 `strategy_id`、`account_id` 列；所有账户的规则改写为组合 E，旧格式的建议、处理状态和理论订单一并删除，`ops.backtest_run` 只保留因子研究的运行记录。持仓、流水、净值和分红送转记录不变。
4. 账户建议的交易日是本地最新一根日线的日期，同步完成后统一生成，不再等巡检。
5. 保留因子研究页面：改因子组合之前先在这里检验，再改代码里的默认规则。账户里不能增删因子。
6. 账户建议仍然不读取任何回测、IC 或 Deflated Sharpe 数字，只按固定规则和当天的排名决定买卖。

## 取舍

- 不做兼容：账户规则 JSON 的每个字段都必填，没有缺省补齐；旧建议没有迁移成新格式，而是删除。代价是建议回看、理论订单的历史从迁移那天重新开始。
- 不保留旧系统作为对照：研究结论和数字留在研究记录里，代码要找回只能看 git 历史。
- 账户里不开放因子编辑：避免用户在样本内反复挑因子造成过拟合；研究页面仍然可以自由组合和检验。
- 自然月调仓，不按固定交易日间隔：用户好记，和研究里的每 20 个交易日调仓接近。

## 后果

- 后端少了约一万行代码，接口只剩行情、自选、账户、因子研究、同步和系统几类；前端导航是首页、账户、研究、自选。
- 纯做多的组合跟着大盘涨跌，回撤可能到 30% 左右；样本外的结果部分依赖看过全区间后加入的成分，实际表现可能低于回测，建议先小资金或只记录不执行跟踪几个月。
- 以后想加新的选股方法，先在因子研究里加因子并检验，再决定是否改默认规则；不要恢复信号和策略那一套。
