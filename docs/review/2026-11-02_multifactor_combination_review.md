# 组合策略引入与因子相关性评审

## 结论

当前服务适合把 G2「基本面困境反转」和 G4「特质动量景气龙头」先作为研究页的候选实验，暂不适合把 G1、G3、G5 或 G6 直接作为账户默认策略或可执行组合。G1 和 G5 依赖估值、分红数据的历史覆盖与时点可信度，G3 依赖账户当前无法保存的股票池条件，G6 需要现有单账户模型没有提供的多策略资金配置。所有候选都应先经过统一股票池、执行条件、费用、时间切分和多重检验后的对照实验。

文档提出的因子重复占权问题是可信的设计风险，但当前代码和本次检查没有测出相关系数，不能把「理论上可能高度相关」写成已证实的统计事实。当前实现最需要先处理的是因子缺失时的静默退化：合成会按实际有值权重重新归一，账户仍会正常排名，因此用户可能把一个缺失估值或财务条件的组合当成完整策略使用。

## 结构概览

研究请求在 API 层解析因子、权重、调仓周期和股票池，`factor_lab::load` 读取股票日线、财务、估值和公司行动数据，`process` 完成去极值、标准化、中性化和合成，`evaluate` 或 `simulate` 生成研究结果。账户排名通过 `advice::ranking` 使用同一套 `load` 和 `ranking` 逻辑，但固定使用默认股票池、行业和规模中性化，账户规则只携带因子权重、持有只数和缓冲区。

研究回测能表达 `rebalance`、`boards`、`exclude_small_pct`、`min_amount`、`min_listed_days` 等股票池和执行参数；内置前端预设只有因子、权重和可选 `max_price`，账户规则也不能保存这些研究参数。研究回测默认每固定交易日调仓，账户按自然月末调仓，账户还受整手成交、追高限制、ST 卖出和现金规则影响。

## 发现

### [高] 研究候选的完整策略定义无法进入账户规则

- 原则：信息隐藏、单一事实来源、配置与代码分离。
- 位置：`frontend/src/lib/factors.ts:7`、`backend/src/account/rules.rs:18`、`backend/src/advice/ranking.rs:34`、`backend/src/api/research.rs:306`。
- 现象：内置预设只保存因子、权重和 `max_price`；账户规则只保存因子、权重、`top_n`、`buffer`、现金、追高和 ST 规则。账户排名固定使用默认 `Universe`、`exclude_small_pct = 0` 和月末调仓。研究 API 才能保存板块、剔除小盘比例、最低成交额、上市天数和 5–60 个交易日的调仓间隔。
- 代价：G3 要求主板、剔除最小 30% 股票并取消低价上限，G4 要求最低成交额和上市天数，G2 要求更高的流动性门槛。这些组合即使能在研究 API 中运行，也不能由账户规则完整复现。把研究页的结果套到账户后，实际执行会变成另一个股票池和另一种调仓策略。
- 建议：先把 G1–G5 定义为带完整实验参数的研究配置，至少在保存和展示时同时记录股票池、中性化、调仓、持有数量、缓冲区和费用。若要让某一方案进入账户，先单独做账户规则扩展和对应 ADR，明确哪些参数属于账户策略；在此之前只允许研究验证，不把它设为账户默认值。

### [高] 缺失因子会使组合静默变成另一套组合

- 原则：显式优于隐式、错误处理边界、单一事实来源。
- 位置：`backend/src/analysis/factor_lab.rs:795`、`backend/src/analysis/factor_lab.rs:807`、`backend/src/analysis/factors.rs:542`、`backend/src/analysis/factor_lab.rs:277`。
- 现象：合成时只累加当前股票有值的因子，并按实际使用的绝对权重重新归一；只要实际有值权重达到总权重的一半，股票就能得到合成分数。`earnings_yield` 依赖 `fin.valuation_1d`，`dividend_yield` 依赖 `mkt.adj_event_effective`，财务因子则受报告可用日和 15 个月窗口限制。缺失不会让研究或账户排名失败，也不会在结果中返回每个取样日的实际因子覆盖率。
- 代价：G1 可能在估值缺失时退化为成长和质量，G5 可能长期缺少估值或分红约束；`value_quality_risk` 仍可能返回正常净值和排名。账户用户无法从排名结果判断名义上的因子是否真的参与，后续收益和回撤也无法归因到原组合定义。
- 建议：任何新组合实验先输出每个取样日的因子有效股票数、有效绝对权重、实际权重占比和因此被拒绝的股票数，并统计组合退化日比例。对价值和分红因子设置事前覆盖门槛；覆盖不足时返回「不可验证」或明确标记退化，而不是继续用完整策略名称展示结果。该诊断应先于 G1、G3、G5 和账户默认规则调整。

### [中] 当前相关性字段不足以决定因子权重

- 原则：可测试性、显式优于隐式、单一事实来源。
- 位置：`backend/src/analysis/factor_lab.rs:957`、`backend/src/analysis/factor_lab.rs:1044`、`backend/src/analysis/factor_lab.rs:1125`、`backend/src/analysis/factor_lab.rs:1224`。
- 现象：`factor-test` 的 `correlation` 是每个取样日上经过方向统一、标准化和可选中性化后的因子横截面秩相关的时间平均。计算只在两个因子同时有值且样本达到阈值时累加，没有返回每一对因子的有效取样日数、共同股票数、缺失率或置信区间，也不使用组合权重。结果还包含等权合成列，容易被误读为单个原始因子。
- 代价：一个相关系数可能来自长期完整覆盖，也可能来自少量共同样本；缺失模式不同的财务、估值和分红因子之间还会产生选择性样本。即使横截面相关性较低，经过前 30 只排序、缓冲区、持仓冻结和交易成本后，组合收益序列仍可能高度相关。单看当前字段不能决定 `volatility` 和 `idio_vol` 是否应合并、G1 和 G4 是否重复，或 G3 是否真的能提供防守分散。
- 建议：先保留现有相关性作为初筛，同时补充共同覆盖数量、覆盖比例和按时间滚动的相关性。权重决策至少同时查看：处理后因子相关性、有效权重占比、前 `top_n` 的因子暴露、候选组合的净收益相关性和成本后回撤相关性。暂不引入根据相关系数自动调权的学习式机制，以免在当前样本长度和试验计数下扩大选择偏差。

### [中] 默认组合 E 对低风险机制存在重复计权

- 原则：共同闭包原则、DRY、因子机制的高内聚。
- 位置：`backend/src/account/rules.rs:35`、`frontend/src/lib/factors.ts:18`、`backend/src/analysis/factor_lab.rs:788`。
- 现象：默认组合 E 对 `volatility`、`idio_vol`、`profit_growth`、`accruals`、`liquidity` 各给 1.0 权重。只要五个因子都有值，低风险的两个因子合计占绝对权重的 40%。`volatility` 与 `idio_vol` 都使用最近约 20 个交易日的收益波动，后者再扣除市场共同部分；二者经济含义可能重叠，但当前没有统计验证。`low_vol` 还把 `max_return` 与两类波动一起使用，可能进一步叠加彩票和风险暴露。
- 代价：如果相关性较高，组合名义上是五因子等权，实际更接近低风险机制占主导的组合。机制分组预设把两个波动因子各降到 0.5，说明设计已经识别到重复风险，但账户默认仍使用逐因子等权。组合在微盘和低波动风格同时回撤时，多个因子会同时失效。
- 建议：先用同一股票池和同一预处理测量 `volatility`、`idio_vol`、`max_return` 的共同覆盖与相关性，再做「逐因子等权」和「机制分组等权」的配对消融。若分组方案保留，应把组定义、组权重和缺失规则写入研究配置，避免只在前端预设中以相对权重表达。不要在没有实测相关性和成本结果前直接改账户默认值。

### [中] 因子家族的重复暴露范围大于文档已列的两组

- 原则：共同复用原则、单一事实来源。
- 位置：`backend/src/analysis/factors.rs:59`、`backend/src/analysis/factors.rs:252`、`backend/src/analysis/factor_lab.rs:788`。
- 现象：除 `volatility`–`idio_vol` 外，`liquidity` 与 `illiquidity` 都倾向表达规模或交易冲击，`abnormal_turnover` 与成交活跃度和情绪关注相关，`reversal`、负向 `momentum` 和负向 `momentum12m` 都可能表达不同时间尺度的反转，`roe`、`gross_profitability`、`profit_growth` 和 `accruals` 也可能共享盈利质量信息。处理时其他因子默认对 20 日成交额规模中性化，但 `liquidity` 自身不对该规模变量中性化，因此它仍然主动承担规模暴露。
- 代价：组合加入看似不同的因子时，可能只是增加同一经济机制的投票数；权重、缺失和标准化之后的实际暴露会与因子数量不一致。G2 中 `reversal` 与 `profit_growth`、G1 与 G4 中共同使用 `profit_growth` 的增量，都不能由因子名称判断。
- 建议：把相关性诊断扩展到全部 17 个因子，并按经济机制形成预先登记的分组。每次候选组合至少做组内去重、单因子删除和共同样本对照；相关性只能作为筛选条件，最终仍需用成本后组合结果和事前冻结的证伪标准判断。

### [中] G6 需要新的账户层资金配置模型

- 原则：关注点分离、依赖规则、YAGNI。
- 位置：`backend/src/account/rules.rs:18`、`backend/src/advice/generate.rs` 的账户预算规则、`docs/domains/accounts.md#rules`。
- 现象：一个账户只有一组因子规则和一套持仓，建议生成按这一组排名直接分配到 `top_n` 个股票。当前没有策略子组合、资金比例、独立净值、组合级再平衡或子策略之间的风险约束。
- 代价：G6 的 G3 + G2 杠铃配置无法通过增加一个因子预设实现。把两套因子简单合并会变成新的单一排名，失去两端独立资金配置和风险解释；把两个账户当成组合又没有统一的组合净值和资金约束。
- 建议：当前不推进 G6。只有在确认需要多策略账户后，再单独设计子组合、资金比例、现金归属、交易冲突、组合净值和回测统计，并记录新的架构决策。

## 建议的验证顺序

1. 先做 D0 覆盖率诊断。对全部候选组合报告每个取样日的实际因子覆盖、实际权重和退化比例，特别检查 `earnings_yield`、`dividend_yield`、`profit_stability`。通过研究 API 运行诊断会写入 `ops.backtest_run`，并影响配置试验计数；运行前应冻结配置和日期区间。
2. 在同一股票池、同一日期区间、同一费用和同一调仓口径下比较当前基线与 G2。至少保留纯技术反转、加入 `profit_growth`、再加入 `accruals` 和 `gross_profitability` 的逐项删除对照，输出净收益、信息比率、回撤、换手、覆盖和成本。
3. 对当前 E 比较逐因子等权与机制分组方案。重点观察低风险组的相关性、组合实际暴露、成本后结果和压力区间回撤，不能只看年化超额。
4. G4 使用 `residual_momentum`、`profit_growth`、`gross_profitability`、`idio_vol` 和 `abnormal_turnover` 做独立实验，并删除共同财务因子做增量检验。
5. 估值覆盖和时点门槛通过后再做 G1；分红和历史股票池覆盖通过后再做 G3；G5 放在这两项之后。所有结果都要计入配置去重后的试验次数，并使用预先冻结的证伪条件。
6. 只有候选策略在研究层形成稳定且可解释的证据，且账户规则能够完整表达其股票池和执行口径时，才评估是否修改账户默认值。账户按因子排名直接生成建议，不读取回测显著性，因此不能用研究结果自动替用户切换规则。

## 值得保持的结构

- `analysis::factors` 只负责因子目录和逐证券取值，`analysis::factor_lab` 负责面板、预处理、检验和模拟，职责边界清楚。
- 账户排名复用因子研究的加载和合成路径，降低研究结果与账户排名使用不同算法的风险。
- `factor-test` 已提供方向统一后的因子相关性、衰减、分组收益和挑选偏差统计，为后续诊断保留了入口。
- 因子目录使用 `FactorId` 枚举和穷尽匹配，新增因子时编译器会提示取值和序列化相关位置；现有测试覆盖了回看边界、财务可用日和部分合成行为。
- 账户编辑因子是已采纳的产品决策，因此研究验证与账户规则之间保留了较短的试验路径；同时需要在界面和文档中清楚标识研究配置与账户执行配置的差异。

## 对现有决策的意见

`account_factor_editing` 已明确允许用户直接调整因子，且不强制先回测。这一决策本身没有被本次评审推翻，但它意味着服务不能把「研究页能运行」当作「账户策略已验证」。建议保留用户可编辑能力，同时在账户设置和因子排名结果中增加因子覆盖与退化提示。

`cross_sectional_factors` 和 `factor_only` 关于账户按单一多因子排名、研究结果不直接驱动选股的边界仍然适用。G6 如果要推进，将改变现有账户模型，应走新的 ADR，而不是在现有预设列表中隐含增加多策略配置。

## 未覆盖与待确认

- 本次没有连接数据库，也没有调用研究接口，因此没有给出 `volatility`–`idio_vol`、`liquidity`–`illiquidity` 或其他因子对的当前样本相关系数。
- 本次没有重新核实研究文档引用的估值快照日期、分红记录数量和历史回测数字；这些数字仍按目标文档的 DOC、D 和 H 标签处理。
- 当前相关性计算的平均值、共同样本数与缺失模式需要在团队确认实验区间后复核；研究接口的写库副作用和试验计数规则需要纳入实验登记。
- 本次没有修改业务代码、迁移、配置或目标研究文档；新增的本文档只是评审归档。
